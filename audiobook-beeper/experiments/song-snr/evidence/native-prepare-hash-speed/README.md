# Exact native waveform preparation with unique-hold hashing

Measured on 2026-10-20 for the user request to accelerate encoding and decoding without changing the data format. This completed preparation component extends the separately preserved native-prepare-speed control. It hashes all sixteen unrounded positive finite float64 pulse holds in each source row, compares complete keys on collisions, sorts only the unique rows in the same numeric lexicographic order as NumPy, and remaps inverse IDs. The hash table and merge-sort state are local and reentrant. Tiny clock-derived float differences remain distinct: the whole song still has110 packet shapes. No nominal-hold substitution or rounding is introduced.

The public native_waveform_prepare.reference(model,source,queries) function preserves the original six-state filter recurrence using the same installed NumPy ILP64 OpenBLAS GEMV and exact six-term reduction order. unique_holds(holds) accepts nonempty float64 arrays with16 columns and strictly positive finite intervals; it explicitly rejects positive/negative zero, negative intervals and nonfinite values. Both APIs handle noncontiguous input. Original Python code remains executable and unchanged.

All nine entire sources and explicit16,384-sample nonuniform448/449-T prefix fixtures pass. The bounded fixtures add a documented silent test guard and carry no quality claim. All float64 targets, complete feature sets, priors, inverse IDs and both complete NWFB001/NWFB002 worksets are byte-identical to the original path:22 matching workset pairs. Bias0 and bias512 are included. The song worksets retain138,493,944/138,493,952 bytes and original hashes. All producer identities were checked after the run.
