# Denser live audio decoding

Measured 2026-10-03 on the same complete 186880-sample, 8000-Hz PCM8
excerpt as `experiments/ima-direct-weighted`. This is a codec feasibility
study, not a replacement TRD or an end-to-end PDM quality claim.

## Rate and distortion

All dictionaries are recording-specific, generated by the PC converter,
stored with the audio and included in the byte totals. The original source
and measurement filter are identical for every row. SNR measures codec
error only, before modulation, ULA contention or a speaker circuit.

| Codec | Payload + dictionary bytes | Reduction from IMA | Codec SNR |
|---|---:|---:|---:|
| Existing 4-bit IMA | 93440 | baseline | 24.973 dB |
| Experimental 3-bit ADPCM, step adjustment 6 | 70080 | 25.00% | 20.999 dB |
| Three-sample VQ, 512 entries | 71617 | 23.35% | 21.305 dB |
| Predictive VQ, 512 entries, half predictor | 71617 | 23.35% | 22.185 dB |
| Predictive VQ, 1024 entries, half predictor | 80940 | 13.38% | 24.348 dB |

The last row is the preferred next implementation candidate: a 10-bit index
selects three signed-byte residuals. For each vector, the predictor is half
the last reconstructed signed PCM8 sample, rounded down. Its unsigned
equivalent is `last_u8 // 2 + 64`; add that to each residual. The encoder
rejects vectors that would overflow PCM8, so the decoder needs no saturation
branch. Quantized dictionary bytes and actual reconstructed feedback are
used during encoding and measurement, not ideal floating-point centroids.
The full excerpt has zero decoded overflows. Training clips 19 teacher
residuals, which is separately disclosed in the report.

The 1024-entry choice loses 0.625 dB of codec SNR while saving 12500 bytes,
including its 3072-byte dictionary. Keeping exactly the old 93440-byte
audio-plus-book budget would hold about 27.11 s rather than 23.36 s; this is
only a capacity estimate. The prototype actually expands the dictionary to
4096 bytes and needs another 512 bytes of pointer tables. Final RAM layout,
code and playback overhead must be counted before promising a duration.
The table uses tightly packed indices. The native probe's five-byte groups
would require 77870 payload bytes for the entire excerpt, two bytes more
than its 77868-byte bitpacked representation; total serialized codec data
would be 80942 bytes. This does not change the rounded 13.38% reduction.

Lossless compression of the existing IMA stream has limited headroom here:
byte Huffman payload is 83090 bytes (11.08% saving, before its codebook),
while gzip is 81119 bytes (13.19%). These are host size measurements, not
Z80 decoding benchmarks. They add work before the existing IMA decoder;
predictive VQ replaces that decoder. Do not infer a runtime guarantee from
entropy or compressed size. Plain 3-bit ADPCM is not selected because it
loses about 4 dB before the PDM stage.

## Native Z80 decoder proof and limits

The standalone [assembly](probe-pvq-decoder.asm) is compiled by pyz80; Python
only supplies dictionary and stream data. Four indices use five bytes:
one byte contains four two-bit high fields, followed by four low bytes.
The test emits PCM8 to port 01 for the native harness; this is not a beeper
player. Its first 8196 samples (683 complete 12-sample groups) match an
independent scalar reconstruction exactly, all memory remains unchanged,
and every measured output interval matches the instruction count.

| Decoder path | Native T-states, excluding test driver |
|---|---:|
| Within a vector | 51 |
| New vector, existing header | 193 |
| New header and vector | 216 |
| Mean over 12 samples | 100.25 |
| Existing direct IMA decode and nibble control | 131 |

Counts use EXX 4; DEC IY byte 8; JR NZ 12/7; LD IY byte,n 11;
LD A,(DE) 7; INC DE 6; register LD 4; LD H,n 7; table read 7;
AND n 7; RLCA 4; SRL r 8; ADD A,n 7; LD A,IXH / LD IXH,A 8;
INC L 4 and ADD A,B 4. The common path is
`4+8+12+7+4+4+8+4=51`. New-vector work substitutes the branch path
and adds pointer/predictor preparation: 193. A new header adds 23: 216.
The test-only OUT (n),A 11 plus JP 10 contribute another 21 to measured
intervals; the verifier explicitly removes neither hidden waits nor work.
The mean is `(8*51 + 3*193 + 216)/12 = 100.25`, saving 30.75 T (23.47%).
The worst boundary is **85 T more** than the old 131-T decoder budget.

At 8000 samples/s and 3546900 Hz, a sample has 443.3625 CPU T on average.
The current complete ordinary player uses 423 T before contention, of
which 131 T is IMA work. Replacing only that average work suggests
392.25 T, but this is not an executable player timing result.

Integration must prefetch the next vector's address over earlier output
slots or stage a small PCM block in a ring buffer. The two 51-T paths each
leave 80 T relative to the old decoder budget, sufficient in aggregate
for the 85-T boundary excess, but transfers, dispatch and bank edges still
need a concrete instruction schedule. A buffer absorbs bursts; it cannot
repair inadequate average throughput. The prototype uses IX/IY state
that overlaps the current packet dispatcher, so it is not a drop-in patch.
Require a complete PDM assembly, all bank/loop edges, cold Fuse output and
both-loop quality/speed checks before selecting it in the converter.

The first native assembly attempt used unsupported INCBIN syntax. Replacing
it with this project's MDAT directive succeeded; no failed build is called
a runtime test. This study changes no release player or root disk.

## Reproduction

```powershell
python audiobook-beeper/probe_dense_codecs.py --input audiobook-beeper/experiments/ima-direct-weighted --output build/dense-codecs --ffmpeg <ffmpeg.exe>
python audiobook-beeper/verify_pvq_decoder.py --input build/dense-codecs --output build/dense-codecs/native
```

Use the project's Python packages (`numpy`, `pyz80`, `z80`) on PYTHONPATH.
The full [comparison](experiments/dense-codecs/report.json) includes all ten
cases; the [native report](experiments/dense-codecs/native/report.json)
states its partial-source scope. No new end-to-end 20-dB result is claimed.
