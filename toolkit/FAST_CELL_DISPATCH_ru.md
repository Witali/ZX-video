# Быстрый обход масок экранных ячеек

19 сентября 2026. База `1ebb4ec`, неизменный FSC2/FSA2 без титров,
4221 кадр, прежние разрешение и AY. Весь общий путь маски → восстановление
→ вывод → публикация исполнен одним Z80; ZX0 пока проверяется отдельно.

## Изменение и точные такты

Прежний путь перебирал восемь битов каждой маски через EXX, SLA B,
счётчик E' и условные переходы. Новый путь разворачивает восемь проверок:
`ADD A,A; CALL C,draw_cell; INC L; INC E`. Подпрограмма сохраняет маску
через EX AF,AF'. Нулевая маска сразу продвигает оба указателя на восемь
столбцов. Вывод плотной полосы и копия всех атрибутов прежние.

Стоимость маски с P установленными битами (от первого EXX до перехода
на следующую маску):

- База: 28 + 8×56 + 22 + 277×P = **498+277×P T**.
- Новая ненулевая: 21 + 14 + 8×22 + 22 + 296×P = **233+296×P T**.
- Новая нулевая: 21 + 14 + 30 + 10 + 22 = **97 T**.

Непомеченная ячейка нового прохода: 4+10+4+4 = **22 T**.
Помеченная: 4+17+289+4+4 = **318 T**. Подпрограмма 289 T включает
4×43 для пикселей, 3×23 переходов строк, два исправления адреса по 15,
две EX AF,AF' по 4 и RET 10. Взятая CALL стоит 17, невзятая 10.

Полная формула от входа до RET, включая 80 LDI карты, paging и атрибуты:

```text
прежде: 58784 + 4793*D + 4*O + 277*P
теперь: 37584 + 5853*D + 4*O + 296*P - 136*Z
дельта: -1060*(20-D) + 19*P - 136*Z
```

D — число плотных полос (четыре FF), O — нечётные плотные полосы,
P — отмеченные ячейки остальных полос, Z — нулевые байты их масок.
Пустой кадр: **58784→26704 T**, −32080; плотные полосы не замедляются.
Код со состоянием **724→769 байт (+45)**, конец **9301**, до AY с 9400.
Новых таблиц или входных байтов не требуется. Генерация без опции
побайтно совпадает с прежним кодом.

Времена взяты из [таблицы Zilog](https://www.zilog.com/docs/z80/um0080.pdf)
и сверены с фактической длительностью каждой исполненной инструкции.

Самый дорогой кадр остаётся **3686**. Для каждого кадра разница точно равна
формуле; все остальные стадии сохраняют прежнее число тактов. Экраны,
предыдущий видимый экран, компактный кадр, защитная область TR-DOS,
входы, таблицы и стек проверены. Обвязка по-прежнему 363 T; её операнды
переместились вместе с состоянием вывода, последовательность инструкций та же.

С ранее измеренным банковым ZX0 раздельная сумма **1612812551 T**,
среднее **382092,526 T**, номинальный средний остаток **43355,474 T**.
Пакетный вход/его копии, AY, ULA и диск ещё не включены. Это **не** проверка
полного времени кадра или устойчивости дисковой подачи. Поток прежний:
**1917975 байт ZX0 с AY**, без дополнительной потери пикселей.

## Проверки и решение

Девять тестов вывода и общей памяти прошли: все 256 масок, пустые/плотные
полосы, очистка относительно n−2, обе страницы и AY IRQ после каждой
инструкции, включая сохранение AF'. Полный прогон 4221 кадра завершён.
Первичная сводка ошибочно требовала идентичности операндов обвязки;
проверка уточнена для переместившегося состояния вывода. Сам CPU-прогон
прошёл сразу; незавершённых/прерванных запусков нет.

Принять новый обход для следующей интеграции. Он почти не помогает
плотным тяжёлым кадрам, поэтому далее проверяется
[выборочное заполнение кэша](SPARSE_MOTION_CACHE_ru.md). TRD пока прежние.

```text

python toolkit/summarize_fast_cell_dispatch.py --baseline toolkit/raw_attributes_128_metadata_cpu.json --candidate toolkit/fast_cell_dispatch_pipeline_cpu.json --stream .tmp/raw_attributes_128/cells.raw --banked toolkit/banked_zx0_fast_cpu.json --storage toolkit/raw_attributes_128_zx0.json --output toolkit/fast_cell_dispatch_summary.json
```
