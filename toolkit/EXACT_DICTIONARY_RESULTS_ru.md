# Точный словарь: размер против дискового буфера

Дата: 17 сентября 2026. База: `27d2c92`, выпуск `69754f3`.
**Статус: полный офлайн-опыт; новый Z80-декодер и TRD не созданы.**

## Результат

Увеличение словаря с 256 до 2048 фрагментов сэкономило **4485 байт (0,136%)**
после ZX0 в проверенном формате. При 4096 фрагментах поток стал больше,
чем с 256. Оснований уменьшать буфер выпуска ради этого небольшого
выигрыша пока нет; само направление словарей этим опытом не исчерпано.

| Фрагментов | Индексы | RAM компактно / развёрнуто | Видео + заголовки ZX0 |
|---|---|---:|---:|
| 256 | Однобайтовые | 1280 / 2304 байта | 3301039 байт |
| 2048 | Частые короткие, остальные расширенные | 10240 / 18432 байта | **3296554 байта** |
| 4096 | Частые короткие, остальные расширенные | 20480 / 36864 байта | 3301676 байт |

Во всех трёх случаях словарь меняется раз в 1024 кадра, включая последний
неполный участок; ZX0 v2 **quick (-q)**, блоки 6144 байта, заголовок каждого
блока 4 байта. Таблицы словаря и командные байты включены в поток до ZX0.
Смена ширины индекса — часть сравниваемого варианта, не изолированный
эксперимент только с количеством записей. Оптимальный режим ZX0 здесь
не измерялся. Сохранено 741 + 693 + 681 = **2115** проверенных блоков в отчётах.

Размеры относятся только к видео. Не включены AY, загрузчик, новый код,
дисковые заголовки/округление и повтор словаря на границе дискет. Даже
3296554 байта видео превышают прежний бюджет двух TRD 1291776 байт.
Число работоспособных дискет по этому архиву не определялось.

## Постановка

Взяты все **4971** принятых компактных экрана, включая титры.
SHA-256 состояний: `9cc006a31408e2c3c3f96f96901b003756c2a480497e12d6b124baedafaeb35d`.
Изображение, атрибуты и последовательность кадров сохраняются побайтно.
Аудио не перекодируется этим опытом.

Один фрагмент — ячейка 8×8 физических пикселей: четыре компактных
bitmap-байта и один атрибут. Таблицу строит ПК по частоте **изменённых**
ячеек, записи с единственным использованием исключаются. Это точный
словарь, а не замена на похожий рисунок без поправок.

Поток содержит три команды: пропустить, взять индекс, передать буквально.
Каждая команда охватывает 1–64 ячейки. Группа начинается с числа кадров,
числа записей и таблицы. Предсказание сбрасывается в ноль на границе группы.
Номер кадра восстанавливается по заполнению всех 768 позиций.

Проверены **29 вариантов**:

- 21 с фиксированной шириной индекса: 0/128/256/512/1024/2048/4096 записей,
  группы 64/256/1024 кадра. Нулевой словарь — контроль того же формата.
- 8 с короткими кодами для частых записей: 512/1024/2048/4096 записей,
  группы 256/1024 кадра. Индексы 0–254 занимают байт, остальные — FF и u16.
- Все варианты проверены независимым разборщиком; восстановленные состояния
  сравнивались с полным исходным массивом.

Предварительный отбор: DEFLATE целого потока и блоков 6144 байта. Лучший
результат DEFLATE с блоками — 3148835 байт (2048 записей, короткие коды,
1024 кадра). Это способ отбора, **не** предсказание размера/скорости ZX0.
Затем три выбранных варианта прошли настоящий ZX0 и независимую распаковку
каждого блока. Прямого замера «новый словарь быстрее старого PLAYER» нет.

## Что значит для памяти и скорости

Разрешение использовать все 128 КБ записано в [AGENTS.md](../AGENTS.md).
См. [карту памяти и разбор Bad Apple](BAD_APPLE_AND_128K_ru.md).

Компактные 2048 записей помещаются в один выделенный банк; кольцо тогда
сократится с 80 до 64 КиБ (320 → 256 секторов). Развёрнутые 2048 записей
требуют больше банка. Если выделять только целые банки кольца, понадобится
два и останется 48 КиБ. Можно исследовать сочетание одного банка со
свободным участком, но это другое размещение и дополнительные переключения.
Служебные данные будущего декодера в эти размеры ещё не входят.

В отчётах отдельно приведены модели для 5 и 9 байт на запись. Они считают
отнятые целые банки, не используют промежутки и **не** являются выбранным
распределением RAM. Небольшой словарь может поместиться в зазорах текущей
карты без уменьшения кольца, после проверки записей/стека/банков.

Есть ещё ограничение: этот опыт использует предсказание **n−1**. В нашем
плеере задний экран хранит **n−2**. Нельзя напрямую перенести команду
«пропустить»: нужен другой предиктор либо подготовка копии предыдущего
экрана. Копирование, разворачивание фрагментов, записи атрибутов и чтение
секторов необходимо включить в будущую оценку CPU и расписания.

Инструкции текущего PLAYER не менялись: **дельта горячего пути 0 T**.
T-states предлагаемого декодера пока не измерены. Этот опыт не подтверждает
новые интервалы видео/AY и не заменяет проверенный выпуск из 14 TRD.

## Решение и следующие проверки

1. Не менять распределение памяти выпуска по результату этого формата:
   выигрыш 4485 байт слишком мал, а сокращение запаса чтения ещё не проверено.
2. Сравнить словарь точных XOR-поправок, предикторы n−1/n−2 и словарь
   рисунков с точными поправками. Последний может использовать сходство
   фрагментов без потери качества.
3. Проверить небольшие блоки 8×4 с отдельными атрибутами и вертикальные серии
   относительно нынешних ячеек/строк; считать таблицы и команды целиком.
4. Для перспективного формата измерить переделанный Z80-декодер, затем
   сравнить кольца 80/64/48 КиБ полным CPU/Fuse-прогоном. Принимать только
   сохранение экранов/AY, шести полей на кадр, отклонения ≤1 мс и отсутствие
   недогрузок. Две дискеты остаются целью, результат ещё не получен.

## Воспроизведение

`CHECKPOINT` — `source/conversion.npz` полной сборки, `ZX0` — исполняемый
файл ZX0 v2. Скрипты и JSON сохранены в репозитории; промежуточные потоки
лежат в игнорируемом кэше и воспроизводятся из принятого входа.

```text
python toolkit/probe_exact_dictionary.py --checkpoint CHECKPOINT --output toolkit/exact_dictionary_measurements.json --cache .tmp/exact_dictionary
python toolkit/probe_exact_dictionary.py --checkpoint CHECKPOINT --output toolkit/exact_dictionary_tiered_measurements.json --cache .tmp/exact_dictionary --index-mode tiered --groups 256 1024 --entries 512 1024 2048 4096
python toolkit/probe_zx0_storage.py --raw .tmp/exact_dictionary/group1024_entries256.raw --block-bytes 6144 --quick --zx0 ZX0 --cache .tmp/dictionary_zx0 --output toolkit/exact_dictionary_zx0_256_measurements.json
python toolkit/probe_zx0_storage.py --raw .tmp/exact_dictionary/group1024_entries2048_tiered.raw --block-bytes 6144 --quick --zx0 ZX0 --cache .tmp/dictionary_zx0_2048 --output toolkit/exact_dictionary_zx0_2048_measurements.json
python toolkit/probe_zx0_storage.py --raw .tmp/exact_dictionary/group1024_entries4096_tiered.raw --block-bytes 6144 --quick --zx0 ZX0 --cache .tmp/dictionary_zx0_4096 --output toolkit/exact_dictionary_zx0_4096_measurements.json
python -m unittest discover -s toolkit -p test_exact_dictionary.py -v
```

Четыре теста с вручную составленными потоками пройдены: расположение
пикселей/атрибутов и сохранение кадра, сброс между группами, граница индексов
255/256, отклонение повреждённых команд/индексов/обрезанного потока.

Данные: [фиксированные индексы](exact_dictionary_measurements.json),
[короткие частые индексы](exact_dictionary_tiered_measurements.json),
[ZX0 256](exact_dictionary_zx0_256_measurements.json),
[ZX0 2048](exact_dictionary_zx0_2048_measurements.json),
[ZX0 4096](exact_dictionary_zx0_4096_measurements.json).
