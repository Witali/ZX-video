# Более компактные таблицы при самостоятельном запуске диска

2026-09-24, база `b77a756`. Основной формат сохраняет независимую загрузку
каждой TRD. Вариант с обязательным предыдущим томом остался отдельным
[экспериментом](WARM_CONTINUATION_ru.md).

## Изменение

Необязательный `--startup-delta` доступен в `build_fap3_trd.py` и
универсальном `convert_video.py`. Для 16-КиБ банка таблиц сохраняются
`d[0]=x[0]`, `d[i]=(x[i]-x[i-1]) mod 256`, затем применяется обычный ZX0.
Загрузчик восстанавливает исходный банк накоплением суммы по модулю 256.
Выбор выполняется отдельно для конкретных таблиц: если число секторов
не уменьшается, сохраняется прежний способ. В метаданных секции отмечены
реальный выбор, контрольная сумма восстановленных/хранимых данных и такты.

Для опорного фильма: **5483 → 4120 байт**, **22 → 17 секторов** таблиц
на каждом диске. После загрузки все 16 384 байта совпадают. Кадровый код,
пакеты, разрешение, пиксели и AY не меняются. Дополнительного постоянного
буфера нет; проход выполняется непосредственно в банке 6 до воспроизведения.

Перед реализацией проверены 20 вариантов хранения с точным обратным
преобразованием: разности/XOR с шагами 1/2/16/256/512, вторая разность,
перестановки, генерация сдвигов и канонические длины Хаффмана.
Большинство хуже исходного ZX0. Простая разность на один байт — лучший
из проверенных вариантов с коротким прямым обратным проходом.
Канонические длины дают **2476 байт**, однако Z80-генератор таблиц ещё
не реализован и его размер/время в эту оценку не включены.

## Такты и память

Горячий путь не изменён, Δ **0 T** на кадр/IRQ/сектор.
Новая процедура занимает **17 байт**, вызов ещё 3 байта, всё внутри
прежнего bootstrap. Стеки, экраны, таблицы и кольцо 64 КиБ не расширяются.

Детерминированный проход, без ROM/диска/IRQ/ULA:

```text
настройка: LD HL,nn 10 + LD B,n 7 + LD D,n 7 + XOR A 4 = 28 T
байт: ADD A,(HL) 7 + LD (HL),A 7 + INC HL 6 + DJNZ 13/8
страница: DEC D 4 + JR NZ 12/7
RET 10
28 + 64*(256*33-5+4+12)-5 + 10 = 541 409 T
CALL 17: всего 541 426 T (раньше отдельного прохода не было: 0 T).
```

Это примерно 153 мс чистого CPU при 3,5469 МГц **один раз при запуске**.
Полный bootstrap также читает меньше секторов и иначе распаковывает ZX0.
CPU-модель с подменёнными услугами диска дала:

| Том | Bootstrap до, T | После, T | Разница |
|---|---:|---:|---:|
| 1 | 2 164 445 | 2 702 917 | +538 472 |
| 2 | 2 428 188 | 2 966 639 | +538 451 |
| 3 | 2 358 332 | 2 897 270 | +538 938 |
| 4 | 2 358 299 | 2 897 237 | +538 938 |

Реальное время загрузки в Fuse: **56,456→55,609 / 55,406→54,557 /
54,755→56,491 / 54,763→56,488 с**. Уменьшение числа секторов не
гарантирует ускорения: изменяется геометрия начала видеопотока и фаза
чтения. Эти интервалы включают ROM, эмуляцию диска, IRQ и ULA; нельзя
называть их разницу отдельно измеренной механической задержкой.

## Размер и полное проигрывание

На одинаковых четырёх диапазонах 1269/1065/861/1026 кадров:
**7759 → 7724 сектора**, экономия **35 секторов / 8960 байт**.
Из них 20 секторов — сами таблицы, остальное — изменение заполнения
последних дорожек. Видеопоток **1 929 627 байт** побайтно прежний.

В трёхтомном контроле с границами 1614/2920/4221:
**7701 → 7687** при ёмкости **7632**. Не хватает **55 секторов / 14 080
байт**; это не доказательство лучшего возможного разбиения.

Восемь полных запусков Fuse: **8442 кадра / 50 652 AY-записи**, каждый
том загружен самостоятельно; **13 030 точных runtime-секторов**, без повторов.
Все восемь банков таблиц проверены полностью при настоящем Z80 bootstrap
с подменённой ROM. В Fuse изображение проверялось по 80 байтам на кадр.
Три перехода томов проходят проверку текста/идентификаторов/полного
начального RAM с подменённой ROM.

| Том | fps до → после | Нарушения номинала до → после | Пропуски полей AY до → после |
|---|---:|---:|---:|
| 1 | 7,9194 → 7,9135 | 1215 → 1215 | 421 → 427 |
| 2 | 7,7179 → 7,7112 | 1020 → 1058 | 524 → 530 |
| 3 | 6,9094 → 6,9061 | 845 → 843 | 1090 → 1093 |
| 4 | 7,2922 → 7,2974 | 1017 → 1017 | 901 → 896 |

Поздние серии после фильтра: восстановлены 5/7/0/1, остаётся по одной
невосстановленной. Максимальное отставание 8,616/10,695/21,951/17,992 с.
Точные сроки и резервный допуск 20 мс не пройдены, физический привод
не проверен. Опция остаётся выключенной по умолчанию: это проверенная
экономия места с самостоятельным запуском, но не готовый выпуск.

Универсальный конвертер также проверен на шести других входах:
**68 кадров / 408 AY / восемь самостоятельных TRD**, все применили фильтр.
Полные CPU-сравнения compact и двух экранов прошли; все Fuse-запуски
завершились. Хеши всех шести FAP3 совпадают с прежними проверками.
Пять простых входов выдерживают сроки; шумовой вход — нет (501 пропуск
полей AY, 78 runtime-чтений). Два перехода маленьких томов прошли.
20 тестов загрузчиков, конвертера и обратного прохода успешны.

## Воспроизведение

```text
python toolkit/probe_startup_tables.py --raw STREAM.raw --zx0 zx0.exe --cache CACHE --report toolkit/startup_tables_probe.json
python toolkit/measure_startup_delta.py --raw STREAM.raw --states conversion.npz --zx0 zx0.exe --fuse fuse.exe --read-cache CACHE --output WORK --report toolkit/startup_delta_fuse.json
python toolkit/test_fap3_disk.py --volumes WORK/delta --output toolkit/startup_delta_swaps.json
python toolkit/check_generic_converter.py --output GENERIC_WORK --ffmpeg ffmpeg.exe --ffprobe ffprobe.exe --zx0 zx0.exe --fuse fuse.exe --trdos-rom trdos.rom --startup-delta --report toolkit/startup_delta_generic.json
python toolkit/archive_deferred_disk.py --source WORK --summary toolkit/startup_delta_fuse.json --output toolkit/startup_delta_evidence
python toolkit/summarize_startup_delta.py --measurement toolkit/startup_delta_fuse.json --generic toolkit/startup_delta_generic.json --generic-baseline toolkit/generic_converter_checks.json --output toolkit/startup_delta_summary.json
```

Исходные данные: FAP3 SHA `1aff3a304635025c…`, states `fdabc3331ee2ce7d…`.
Нужны numpy/Pillow и `PYTHONPATH=toolkit`. Fuse запускать последовательно.
