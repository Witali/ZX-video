# Общая память реконструкции и вывода; выбор фрагментов по времени кадра

19 сентября 2026. База `6103e11`: весь монтаж без титров, **4221 кадр**,
128×96 логических точек, вывод 256×192, 25/3 кадра/с, прежний AY 50 Гц.
Все текущие эксперименты сохраняют пиксели age3 и звук побайтно.
Корневой выпуск `69754f3` с титрами пока не заменён.

## Изменение выбора фрагментов

`probe_delivery_budget.py` использует измеренное время вывода каждого кадра.
Лимит реконструкции = общий ориентир − 8000 T запаса модели − вывод.
Сравниваются обычный выбор фрагментов и замена всех оставшихся фрагментов
с движением, позволяющая убрать копирование кэша стоимостью 60398 T.
Кадр склейки 4086 остаётся независимым от удалённого предшественника.
Группы содержат ровно один кадр. 8000 T — поправка оценки выбора,
**не** измеренная стоимость метаданных, ZX0, AY или диска.
В четырёх кадрах сама модель не смогла достичь заданного лимита:
применён выбор с наименьшим оценённым временем, эта нехватка явно
сохранена в отчёте. Ориентир 375000 не является гарантированной границей.

| Вариант | Быстрых фрагментов | Видео ZX0 | С несжатым AY | Запас 3 TRD |
|---|---:|---:|---:|---:|
| Предыдущий однокадровый FSC1 | 28730 | 1708995 | 1827359 | 110305 |
| Ориентир 375000 T | 61862 | 1833006 | 1951370 | −13706 |
| Ориентир 385000 T | 56892 | 1814845 | 1933209 | 4455 |

Все размеры ZX0 измерены оптимальным ZX0 v2, независимые блоки ≤8192 байт,
с четырьмя байтами заголовка на блок. Каждый блок восстановлен PC-декодером.
DEFLATE не подменяет эти замеры. Вариант 385000 имеет только PC-проверку
кадров и размера; его CPU-время не наследуется от варианта 375000.

## Общий поток со звуком

Вариант 375000 без сжатия AY не проходит по объёму. `cell_audio_stream.py`
создаёт **FSA1**: заголовок FSC1 с другой сигнатурой, затем перед каждой
однокадровой группой — шесть прежних AY-записей. Запись содержит число
изменений и пары `(регистр, значение)`; формат соответствует очереди IRQ.
Новые байты длины не добавлены. Сохраняются и записи без изменений.

- Сырой общий поток: **3079808 байт**.
- ZX0: **1918548 байт** с заголовками, **376 блоков**.
- Экономия относительно отдельного несжатого AY: **32822 байта**.
- Предварительный запас к 1937664 байтам трёх TRD: **19116 байт**.
- Максимум AY на кадр: **74 байта**; восстановлены все **25326 тактов**
  сравнением всех регистров R0..R10 с исходными 9-байтовыми состояниями.
- После разделения потока видео FSC1 и AY совпадают побайтно.

В будущем оба канала смогут пользоваться одной историей ZX0. Пока это
проверка сериализации: Z80 ещё не разбирает FSA1 и не подаёт его в очередь.
Запас предварительный: независимые старты дисков, таблицы/PLAYER,
округление секторов и раскладка ещё могут изменить итог.

## Что выполняет общий Z80-стенд

`frame_output_pipeline.py` исполняет реальную очистку, восстановление,
вывод и переключение в **одном экземпляре CPU и 128 KiB памяти**.
Хост передаёт только распакованные метаданные, кодированные значения
и карту; готовый компактный кадр или экран хост в память не записывает.
Следующий кадр использует действительную память предыдущего вызова.

| Данные | Адреса |
|---|---|
| Экран 5 / экран 7 | 4000..5AFF / C000..DAFF при банке 7 |
| Область TR-DOS, защищена от записи | 5B00..63FF |
| Компактный кадр | 6400..72FF |
| Карта текущего кадра | 7300..734F |
| Кэш движения | 7400..77FF |
| Разовая очистка | с 7B00 |
| Реконструкция / обвязка / вывод | с 8000 / 8F60 / 9000 |
| Тестовый AY/IRQ, таблицы, стек, LUT | 9400..9FFF |
| Очередь AY | A000..A3FF |
| Векторы / маски bitmap / маски attributes | A400 / A4C0 / A640 |
| Два канала значений с защитными байтами | A6A0..B8FF, 4704 байта |
| Таблицы декодера / IM2 / копия карты | B900..BF6F |
| Префиксные таблицы в банке 6 | C000..FFFF |

Вариант 375000 требует максимум **2802 байта** окна значений. Банк 7
E000..FFFF и банки 0/1/3/4 для истории ZX0/дискового кольца пока не
подключены; их свободные адреса не доказывают пригодность будущего расписания.

При старте экраны/кадр/кэш предварительно заполнены A5. Их очищает Z80;
область TR-DOS сохраняет A5. Проверки ловят запись на видимый экран,
повреждение таблиц, выход чтения за входной пакет и ошибку адресации.
В каждый кадр проверяются компактный кадр, оба физических экрана,
позиции обоих каналов, стек и записи порта 7FFD.

## T-states и границы результата

Код реконструкции и код вывода побайтно совпадают с базой. Изменён поток
выбранных фрагментов и добавлена исполняемая обвязка. По таблице Zilog
UM0080, от входа обвязки до RET, без внешнего CALL:

| Операции обвязки | T |
|---|---:|
| Четыре пары LD HL,nn / LD (nn),HL | 104 |
| Указатель литералов: LD HL,(nn) / LD (nn),HL | 32 |
| Начальное состояние битов и флаг кэша | 46 |
| CALL реконструкции | 17 |
| Аргументы вывода и CALL | 40 |
| Обновление сохранённого 7FFD и OUT | 55 |
| Выбор следующего заднего экрана | 33 |
| RET | 10 |
| **Всего** | **337** |

Ранее эти действия выполнял хост и в счётчик они не входили: добавление
обвязки **+337 T/кадр**. Однократная очистка двух экранов по 6912 байт
и области 6400..77FF (5120 байт) стоит **397967 T**, отдельно от кадров.
Для каждого LDIR: 21 T на повторение, 16 T на последнее исполнение.
Копирование карт, paging и вывод атрибутов уже входят во время вывода.

Итоговые полные счётчики и сравнение с прежними группами до восьми кадров:
[delivery_budget_summary.json](delivery_budget_summary.json).
Важное различие баз: прежний счётчик складывал два независимых стенда;
нынешний исполняет их последовательно с новой обвязкой и группами по одному.

Проверены **все 4221 кадр** в общей памяти, включая склейку и EOF:

- Реконструкция + вывод + обвязка: **1310702865 T** вместо 1403831746 T;
  экономия **93128881 T**. Среднее **310519,513 T/кадр**.
- Максимум **405873 T** (кадр 3375), ранее 450831 T. Кадров сверх
  номинальных 425448 T: **939 → 0** для этих стадий. Три кадра превышают
  ориентир выбора 375000 T; у худшего остаётся всего 19575 T.
- ZX0 всего общего потока: **171761112 T**, максимум блока **633994 T**.
  Полный блок нельзя считать короткой атомарной работой между кадрами.
- Сумма измеренных раздельных стадий: **1482463977 T**,
  **351211,556 T/кадр** в среднем. Средний остаток 74236,444 T ещё должен
  оплатить метаданные, AY, вызовы/подачу ZX0, ULA, ROM и дисковый ввод.
- Относительно прежних раздельных FSF/карт и несжатого AY: **+161996 байт**
  (633 дополнительных сектора с округлением) за **46458607 T** чистой
  экономии измеренных стадий. Средний предел окупаемости добавленного
  сектора **20,701 мс**; это расчёт, без измерения дисковода и его расписания.

Отдельный `benchmark_zx0_storage.py` измеряет все блоки FSA1 на Z80.
Его тестовая раскладка памяти отличается от общей: **сумма CPU-стадий
не является доказательством общей раскладки или плавных 25/3 кадра/с**.
Метаданные пока разворачивает хост; ZX0 не включён в общий цикл.
Нет ожидания шестого прерывания, ULA contention, ROM, физического диска
и полного расписания AY. Переключение стенда немедленное, без pacing.

Тесты общего пути включают движение, три пространственных предиктора,
четыре типа полных фрагментов, оба экрана и переходы страниц входа.
Настоящий AY ISR вызывается после каждой инструкции двух тестовых кадров,
включая границы EXX, CALL/RET и публикации 7FFD. Это проверка сохранения
регистров и памяти, **не** моделирование частоты 50 Гц или снабжения очереди.
