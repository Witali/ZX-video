# Восстановление частотного алфавита без таблицы

18 сентября 2026, база `cb7031f`. Ускорен отдельный Z80-примитив для
[четырёхуровневого частотного алфавита](MOTION_ALPHABET_RESULTS_ru.md).
Он работает со всеми возможными байтами, не только встреченными в фильме.
Потоки, пиксели, атрибуты, звук, разрешение и частота видео не меняются.

## Формулы

Для двух битов предсказанного уровня `ph,pl` и кода поправки `ch,cl`
результат имеет биты:

```text
qh = ph XOR cl XOR (ph AND (ch XOR cl))
ql = pl XOR (ch AND NOT(ph AND pl)) XOR (cl AND (ph OR pl))
```

Операции над байтом вычисляют сразу четыре двухбитных пикселя. Сдвиг
совмещает старшие биты с младшими; маска `AAh` в конце объединяет две
плоскости. Таблица обращений к памяти не нужна. Формулы применимы именно
к сохранённой таблице `[[0,2,1,3],[1,2,0,3],[2,3,1,0],[3,2,1,0]]`.
Скрипт проверяет совпадение этой таблицы с отчётом сжатия.

## Измеренные примитивы

Вход B — байт предсказания, C — байт поправки; результат A. Считалось
время от входа до RET включительно.

| Вариант | T-states | Код, байт | Таблица, байт | Сохраняемые регистры |
|---|---:|---:|---:|---|
| Прежняя общая таблица | 148 | 35 | 256 | B/C/E/H |
| Первые формулы с дополнительными временными регистрами | 116 | 28 | 0 | B/C |
| Формулы с прежним набором сохраняемых регистров | **117** | **28** | **0** | B/C/E/H |

Последний вариант изменяет D/L/флаги, как и прежний. C временно вращается
внутри процедуры, но восстанавливается к выходу. Экономия **31 T (20,95%)**,
7 байт кода и 256 байт таблицы. Вариант 116 T сохранён как промежуточный
опыт; выигрыш одного T не оправдывает изменение соглашения о регистрах.

Для сравнения, обычный XOR занимал 18 T; новый частотный вариант всё ещё
дороже него на 99 T. Размеры сжатия XOR и частотного алфавита различаются,
поэтому скорость всей доставки надо сравнивать с учётом диска и ZX0.

Подсчёт по [Zilog UM008011-0816](https://www.zilog.com/docs/z80/um0080.pdf),
стр. 71, 145, 158, 160, 162, 175, 209, 213, 226, 285; машинный код,
команды и их времена сохранены в [JSON](frequency_logic_measurements.json).
Табличный, первый и окончательный варианты исполнены для каждой из
65536 пар байтов, всего **196608 исполнений**. Проверены результаты,
постоянное время, стек и заявленные сохраняемые регистры нового кода.

По 1652491 исправляемому байту рисунка полного фильма уменьшение только
этих операций составляет в среднем **10305,214 T/кадр**, максимум
**61504 T/кадр**. Это расчёт по ранее измеренному числу поправок,
не замер полного декодера. CALL, загрузка/запись, маски, векторы движения,
ZX0, paging, IRQ, ULA, TR-DOS ROM и физическая задержка диска исключены.
Время чтения битов Хаффмана, исследуемого отдельно, сюда также не входит.

## Проверка интерпретатора

Добавлены отсутствовавшие CPL, RLC/RRC для обычных регистров и `(HL)`
в `validate_fast_sparse.CPU`; индексные варианты не добавлялись.
Два теста проверяют все 256 входных значений, исходный перенос, адресат,
моделируемые флаги Z/C и времена 4/8/15 T: всего **9216 отдельных команд**.
Интерпретатор и ранее моделировал только нужную проекту часть флагов;
проверка не заявляет полноценную эмуляцию всех флагов Z80.
Прошли также 5 существующих тестов проигрывателя, включая IRQ, переходы
секторов/экранов и точные времена ветвей. Их прежние результаты сохранились.

## Решение

Использовать примитив 117 T при дальнейшей реализации декодера этого
алфавита. Освобождение 256 байт полезно для таблиц распаковки. Полное
распределение 128 КиБ и уменьшение кольца диска пока не проверялись.
PLAYER/TRD не менялись, изменение встроенного горячего пути **0 T**;
новых полных Z80/Fuse/дисковых замеров нет. Это не подтверждение 8⅓ fps
для нового формата и не новый выпуск.

```text
python toolkit/benchmark_frequency_logic.py --alphabet-report toolkit/motion_alphabet_measurements.json --previous-cpu-report toolkit/motion_alphabet_cpu_measurements.json --output toolkit/frequency_logic_measurements.json
python -m unittest discover -s toolkit -p test_frequency_logic_cpu.py -v
python -m unittest discover -s toolkit -p test_uncontended_player.py -v
```
