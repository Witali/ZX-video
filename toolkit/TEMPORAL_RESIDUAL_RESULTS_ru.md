# Маски изменений и ограниченное удержание ячеек

Дата: 18 сентября 2026. База `a13c3fe`, выпуск TRD остаётся `69754f3`.
**Офлайн-опыт; цель трёх дискет и скорость нового декодера не подтверждены.**

## Что проверено

Все 4971 кадр принятого фильма, прежние 128×96 логических / 256×192
физических пикселя, 25/3 кадра/с. Звук AY 50 Гц не меняется и в размеры
видео не включён. Атрибуты каждой ячейки остаются побайтно исходными.

Новый поток `TRS1` хранит маску ненулевых байтов XOR и сами байты поправок.
Маски сгруппированы по 8 или 16 кадров, затем идут значения каждого кадра.
Это ограничивает буфер масок 3840 или 7680 байтами. Предыдущий опыт
с разделением масок всего фильма требовал бы гораздо большего буфера.
Проверены предсказания n−1 и n−2; история продолжается между группами.
На границах будущих дискет понадобятся начальные кадры/сброс истории;
их дополнительные расходы здесь не учтены.

Ограниченный фильтр на ПК предлагает оставить рисунок ячейки прошлого
кадра, если относительно **текущего исходного кадра** меняется максимум
1 или 2 логических пикселя, каждый не более чем на четверть заполнения.
Дополнительный предел RMSE усреднённого по 2×2 RGB — 24. Ошибка не
накапливается относительно отфильтрованного эталона: эталон всегда исходный.
Проверены пределы 1, 2 и неограниченное число последовательных неточных
удержаний. Точное совпадение с исходным кадром удержанием не считается.

Также измерены контроль без потерь и прежний словарный кандидат
`bitmap256_rmse24_group512` без изменения его изображения. Всего
8 последовательностей × 4 раскладки = **32 полных обратных проверки**.

Неограниченный вариант оставлял отдельную неточную ячейку до **162 кадров**,
то есть 19,44 с. Его не принимаем: небольшая ошибка отдельного кадра
не оправдывает столь долгое сохранение неверной детали. Даже этот вариант
по предварительному размеру ещё не достигает бюджета трёх дискет.

Для настоящего ZX0 выбран осторожный вариант с максимумом двух пикселей
и **одного** последовательного неточного удержания. Это допускает локальную
задержку детали на 120 мс и ещё требует проверки в движении.

## ZX0 и качество выбранного варианта

Оптимальный ZX0 v2, блоки 8192, включая 4-байтовые заголовки:
**2853363 байта** видео, 599 независимо распакованных блоков.
Контроль без потерь **того же формата**: 2920696 байт, 608 блоков.
Фильтр сэкономил **67333 байта, 2,31%**; всего проверено 1207 блоков.
Результат на 41313 байт (1,43%) меньше прежнего лучшего замера без потерь
2894676, но у него другой формат/буферизация и здесь допускается ошибка.
Это не изолированная оценка эффективности фильтра.

Бюджет трёх TRD до дополнительных расходов — 1937664 байта.
Кандидат превышает его на **915699 байт ещё до звука**. Ранее измеренный
звук добавляет 77696 байт; загрузчик, рост декодера, границы томов,
интерливинг и округление секторов также должны учитываться при сборке.

| Качество относительно принятого Spectrum-изображения | Результат |
|---|---:|
| Изменённые физические RGB-пиксели активной области, среднее | 0,084185% |
| Максимум на одном кадре | 0,420464% |
| SSIM яркости, средний / минимальный | 0,995884 / 0,973526 |
| 1-й процентиль SSIM | 0,984217 |
| PSNR усреднённого 2×2 RGB, весь фильм / худший кадр | 37,104 / 30,281 дБ |
| Дополнительные целиком повторённые кадры | 0 |
| Максимум последовательных неточных удержаний ячейки | 1 |

Чёрные полосы исключены, область сравнения 256×144. SSIM не означает
«процент качества». Метод тот же, что в предыдущем
[отчёте](BOUNDED_DICTIONARY_RESULTS_ru.md). Просмотрены шесть худших
статичных кадров: 667, 2511, 3509, 3829, 2509, 4718. Видны редкие изменения
точек; крупные формы и цвета сохранены. Это не просмотр всего движения.

## Проверки и решение

- Все 32 потока независимо восстановили ожидаемые кадры; контроль без
  потерь сохранил SHA-256 `9cc006a31408e2c3c3f96f96901b003756c2a480497e12d6b124baedafaeb35d`.
- SHA-256 выбранных кадров:
  `2e2c8ac4406f36de104bbef17b94faa39ae7b68104e806998448673b551f996a`.
- Пять тестов проверяют независимо составленный поток, n−2, границы групп,
  ограничение длительности удержания, отсутствие накопления ошибки и
  отбрасывание повреждённых потоков. Все пройдены.
- SSIM вычислен для всех 4971 кадров; атрибуты точные, звук не менялся.
- PLAYER и TRD не менялись, **изменение горячего пути 0 T**. Затраты нового
  декодера, копирование n−1, paging, IRQ и доставка с диска ещё не измерены.
  Размер буфера масок не включает ZX0, экраны, код, стеки, AY и TR-DOS.

В выпуск не включать: объём остаётся выше бюджета, проверка движения
и Z80/Fuse не выполнена. Сохранить поток с ограниченным буфером как
контроль для компенсации движения. Не усиливать удержание ради размера.

## Воспроизведение

`CHECKPOINT` — принятый `source/conversion.npz`; `DICTIONARY` — результат
предыдущего опыта `bitmap256_rmse24_group512.npz`; `ZX0` — исполняемый файл
ZX0 v2. Сценарии сохраняют кэши отдельно от Git.

```text
python toolkit/probe_temporal_residuals.py --checkpoint CHECKPOINT --dictionary-candidate DICTIONARY --cache .tmp/temporal_residuals --output toolkit/temporal_residual_measurements.json

python toolkit/probe_zx0_storage.py --raw .tmp/temporal_residuals/exact_n1_g16.raw --block-bytes 8192 --zx0 ZX0 --cache .tmp/temporal_zx0 --output toolkit/temporal_residual_zx0_control_measurements.json
python toolkit/review_bounded_dictionary.py --reference CHECKPOINT --candidate .tmp/temporal_residuals/temporal_p2_hold1_rmse24.npz --output toolkit/temporal_residual_quality_review.json --contact-sheet .tmp/temporal_residuals/comparison.png
python -m unittest discover -s toolkit -p test_temporal_residuals.py -v
```
