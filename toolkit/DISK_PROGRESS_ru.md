# Прогресс видео на текущей дискете

19 сентября 2026, база `7608922`. По уточнению пользователя **100% —
последний показанный кадр текущей дискеты**. Следующая дискета начинает
полоску с нуля; длительность всего мультфильма в расчёте не используется.

## Реализация

Белая полоска 256×2 пикселя в нижнем поле, строки y=184 и 185. Есть
64 шага по 4 пикселя, без текста и числовых процентов. Цвет знакомест
нижней строки задаётся один раз; их бумага остаётся чёрной. При каждом
шаге записываются **только четыре экранных байта**: по два в банки 5/7.
Остальные байты полей и активная картинка остаются прежними.

Для диска с N кадрами шаг k наступает после показа `ceil(k*N/64)`-го
кадра. Таблица из 64 однобайтовых интервалов вычисляется при сборке
этого тома. Z80 только уменьшает счётчик: делений и вычисления процентов
в проигрывателе нет. Последний шаг всегда приходится на кадр N.
Поддерживаются N=1..16320; для коротких томов несколько шагов выполняются
за один кадр. После последнего кадра счётчик останавливается.

`disk_progress_z80.build(frames_on_disk)` требует явного числа кадров
этой дискеты. При загрузке следующего тома нужно загрузить его модуль
с его таблицей интервалов и вызвать `reset` до включения воспроизведения.
Reset очищает только две строки полоски, устанавливает её атрибуты на
обоих экранах и восстанавливает счётчики. `tick` вызывается **только из
publish_bridge**, после публикации кадра и возврата банка 7; подготовка
кадра и предварительное чтение диска индикатор не продвигают.

Это подключено к исполняемому FAP2/FAP3 кандидату с zero-copy и чёрными
полями. Сборщик окончательных томов должен передавать фактическое число
кадров каждого тома. Непрерывный тестовый поток всего фильма сам по себе
не определяет границы физических дискет; опция `--progress-frames`
задаётся явно, проверка запрещает пересечь эту границу без нового тома.

## Память и такты

Модуль **244 байта** занимает банк 7 DCE0..DDD3, включая 7 байт состояния,
7 байт начального состояния и таблицу 64 байта. До таймера DE00 остаются
44 байта. Он находится после zero-copy парсера (FAP3 заканчивается DCCB,
FAP2 — DCD4), не отнимает память у ZX0 history, буферов диска и AY.
В фиксированном publish_bridge добавлено 6 байт, всего **250 байт**.
Новых данных в покадровом потоке — **0**. Изменение размера загрузочного
файла и округления по секторам надо проверить при сборке реальных томов.

По таблице инструкций Z80; вызов штатного publish_bridge уже был в базе.
Дополнительные CALL restore_bank7 + JP tick стоят **27 T**. В таблице
указаны добавленные к прежнему проигрывателю такты, без IRQ/ULA/ROM/диска:

| Путь | Сам tick | Вместе с мостом | Прежний индикатор | Разница |
| --- | ---: | ---: | ---: | ---: |
| Шаг не изменился | 50 | 77 | 0 | +77 |
| Левая половина байта | 300 | 327 | 0 | +327 |
| Правая половина, кроме последней | 314 | 341 | 0 | +341 |
| Последний шаг | 259 | 286 | 0 | +286 |
| Повторный вызов после завершения | 28 | 55 | 0 | +55 |

Первый путь: `13+4+5+4+13+11=50 T`. Подробный листинг с абсолютными
тактами каждой инструкции сохранён в отчёте; исполнение сверяет каждый
шаг и сумму гистограммы. Для N≥64 общая прибавка **77*N+16393 T**.
На тестовом диске в 1000 кадров: **93393 T**, в среднем **93,393 T/кадр**
(около 0,022% бюджета 425448 T). Reset отдельно **4298 T** на загрузку.
Существующее переключение банка используется повторно; новых OUT нет.

Первый проверенный вариант задавал атрибуты при каждом шаге: модуль
254 байта, 6 экранных записей, 96145 T на 1000 кадров. Перенос атрибутов
в reset дал **−10 байт и −2752 T на диск**; итоговый вариант принят.

## Проверки и границы результата

- Полное исполнение счётчика для последовательных тестовых дисков длиной
  1, 2, 63, 64, 65, 128, 1000, 4221, 16320, 999 кадров. Это синтетические
  длины для проверки краёв, **не разбиение мультфильма**. Оба экрана
  сверены после каждого кадра; переходы, 100%, остановка и сброс проверены.
- Интегрированный тест FAP3/ZX0: подготовка прежняя, публикация имеет
  точную прибавку; компактное состояние, активные пиксели и AY совпадают.
- Настоящий код AY ISR вызывается после каждой инструкции reset/моста/
  индикатора. Регистры, страницы, стек и звук сохранены. Это проверка
  прерываемости, отдельно от равномерного расписания 50 Гц.
- **7 тестов прошли**, включая регрессию FAP1 без индикатора. Отдельный
  прогон первых 128 кадров реального фильма с тестовым N=128 завершён:
  все 128 compact/native состояний и 763 прозвучавших AY ticks проверены.
  Foreground **44267453 → 44293702 T, +26249**, ровно формула индикатора.
  Оба варианта имеют 26 опозданий, первое 62, восстановление на 88;
  максимальная фаза **257797 → 259859 T, +2062**. Допуск не соблюдён.
  Это частичный прогон фильма, финальный AY drain и диск не проверялись.
  Просмотрен PNG из фактической видимой RAM после кадра 127: активная
  картинка сохранена, полная белая полоска только в y=184/185, нижнее
  поле вокруг неё чёрное. SHA-256 PNG:
  `772a7cc7fb7f2986c7c1ab6594be1ff7983275e29efc6359d035792ad51bde0b`.

Корневые TRD этим изменением не пересобираются. Требования трёх дискет,
нулевых опозданий, реального дискового чтения и ULA остаются отдельными
проверками; индикатор сам по себе их не подтверждает.
