# FSF1: отдельный канал готовых фрагментов

19 сентября 2026. База `6c5c818`, FHF1 после перевыбора быстрых плиток;
полный age3, 4971 кадр. Пиксели, предикторы, маски, выбранные режимы,
таблицы Хаффмана, разрешение и AY 50 Гц не меняются.

## Формат

Внутри каждой прежней группы сначала записаны все биты Хаффмана, затем
все байты готовых фрагментов. В поле `bits` теперь только Хаффман.
Размер канала фрагментов определяется векторами 85/86/87/88 (16/2/5/1 байт),
дополнительного поля длины нет. Метаданные и границы 641 группы прежние.
Устранено **69918 бит** выравнивания между фрагментами; последний байт
канала Хаффмана по-прежнему дополнен нулями.

Независимый декодер вычисляет предсказания из ранее восстановленных
пикселей, восстанавливает все экраны и заново формирует FHF1. Полученный
FHF1 совпал с исходным **байт в байт**, включая старые выравнивания.
Новый SHA: `82daadf51b0633aa02345b6c184fb1536b8c70f29b85ae4ab2ebb5ad712da212`.
SHA кадров: `4b9e90d22df2809a70c1cb09890de0a9bb0a23d1b1e357b3f6c29ff830cc9c3b`.

## Полные измерения

| Показатель | FHF1 | FSF1 | Разница |
|---|---:|---:|---:|
| Исходные байты | 3031081 | 3022350 | −8731 |
| Optimal ZX0 8192 + заголовки | 2043807 | **2020278** | **−23529** |
| Реконструкция всех кадров, T | 1127839894 | 1124736343 | −3103551 |
| Максимум кадра, T | 308635 | **302728** | −5907 |
| ZX0 всего потока, T | 157425317 | 155550510 | −1874807 |
| Две стадии, T | 1285265211 | **1280286853** | **−4978358** |

Проверены все **4971 кадр**, **641 группа**, **55846 готовых фрагментов**,
**1038625 значений Хаффмана** и **369 блоков ZX0**. Хаффман занимает
4915019 бит, готовые фрагменты — 804330 байт; максимум группы 9159 байт.
Худший кадр реконструкции 4644; кадров >425448 T — 0. Максимум блока
ZX0 698286 T; он не равен задержке отдельного кадра.

Только стадия фрагментов сэкономила **3189544 T**. Изменение битовых
позиций увеличило Хаффман на **85993 T**; все остальные стадии совпали
на каждом кадре. Поэтому выигрыш всей реконструкции **3103551 T**.

С AY требуется **2097974 байта**, до предварительного бюджета трёх TRD
не хватает **160310**. Реальное размещение новых томов/кода не включено.
Новых дисков этот опыт не выпускает.

## Точные такты и память

Таблица инструкций: [Zilog UM008011-0816](https://www.zilog.com/docs/z80/um0080.pdf).
Прежняя подготовка фрагмента: выравнивание/EXX **36+10u T**, перенос
IX→HL **25 T**, сохранение HL→IX **25 T**. Новая: загрузка HL из
`literal_source` **16 T**, сохранение обратно **16 T**. Разница
**−54−10u T** на фрагмент, где u=1 для прежнего невыровненного входа.
IX/C′ остаются указателем и битовой позицией Хаффмана.

| Тело с RET, без внешнего обхода/вызова | FHF1 при u=0 | FSF1 |
|---|---:|---:|
| 85, полные 16 байтов | 546 | 492 |
| 86, повтор строки | 541 | 487 |
| 87, две строки, p единиц в селекторе | 898−10p | 844−10p |
| 88, заливка | 513 | 459 |

Код **3893→3881 байт** (−12), состояние **23→25** (+2), конец **8F42h**.
Таблицы, кэш движения, кадр, метаданные и кольцо диска прежние.
CPU-стенд хранит два непрерывных входных участка, с одним защитным нулём
после каждого: максимум данной группы с защитой 9161 байт. Это размещение
по-прежнему перекрывает экран/TR-DOS и **не является картой готового плеера**.
В плеере нужно организовать два окна/указателя в доступных банках и
проверить их вместе с ZX0, выводом и дисковым расписанием. Уменьшение
кольца без измерения устойчивой подачи секторов не принимается.

Прошли три новых теста: смешанные режимы и группы, точный полный обратный
поток, пустой любой из каналов, неполные биты, повреждённые данные,
формулы и реальный AY IRQ после каждой инструкции. Десять прежних
fast/raw-intra тестов также прошли. При выключенной опции прежний
декодер побайтно совпадает с базовым CPU-отчётом.

**Решение:** принять FSF1 как более компактную и быструю исследовательскую
базу. Плавный вывод 25/3 кадра/с с диском ещё не доказан: суммы не включают
парсер метаданных, окна/paging, развёртку экрана, IRQ/ULA/ROM и диск.
Следующий выбор плиток должен учитывать цену кэша на весь кадр: иногда
замена последних движущихся плиток позволяет полностью пропустить кэш.
Затем нужны фактическая карта 128 КиБ и проверка полного пути в Fuse.

## Воспроизведение

Из рабочего дерева `three-disk-quality`, с зависимостями в PYTHONPATH:

```text
python -m unittest discover -s toolkit -p test_fragment_channels.py
python toolkit/probe_fragment_channels.py --input .tmp/unrolled_fast/target_300000.raw --motion-cache .tmp/spatial_predictors_cost/iteration_1.npz --raw-output .tmp/fragment_channels/separated.raw --output toolkit/fragment_channels.json
python toolkit/probe_zx0_storage.py --raw .tmp/fragment_channels/separated.raw --block-bytes 8192 --zx0 ../audio-fidelity/.tmp/bin/zx0.exe --cache .tmp/fragment_channels/zx0 --output toolkit/fragment_channels_zx0.json --jobs 4
python toolkit/benchmark_zx0_storage.py --raw .tmp/fragment_channels/separated.raw --storage-report toolkit/fragment_channels_zx0.json --cache .tmp/fragment_channels/zx0/optimal --output toolkit/fragment_channels_zx0_cpu.json --baseline-commit 6c5c818
python toolkit/benchmark_spatial_tiles.py --fhs .tmp/fragment_channels/separated.raw --motion-cache .tmp/spatial_predictors_cost/iteration_1.npz --states-sha256 4b9e90d22df2809a70c1cb09890de0a9bb0a23d1b1e357b3f6c29ff830cc9c3b --extended --fast-fragments --unrolled-motion --split-literals --baseline-commit 6c5c818 --output toolkit/fragment_channels_cpu.json
python toolkit/summarize_fragment_channels.py --raw .tmp/fragment_channels/separated.raw --cpu-report toolkit/fragment_channels_cpu.json --output toolkit/fragment_channels_summary.json
```
