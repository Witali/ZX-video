# Повторное использование RAM между томами — отдельный эксперимент

Дата: 2026-09-24. База: `e356874`. Пользователь уточнил, что **каждая
дискета должна запускаться независимо**. Поэтому этот вариант не является
основным форматом и по умолчанию выключен; корневые TRD не заменены.

## Результат

4221 кадр прежнего FAP3 `1aff3a304635025c…` без финальных титров,
25/3 fps, прежние 25 326 AY-записей. Новых изменений пикселей нет.
Весь фильм вмещается в три последовательных тома: **1614 / 1306 / 1301**
кадр. Занято **2543 / 2543 / 2526** из 2544 секторов на диск; свободно
**1 / 1 / 18**, всего 5120 байт. Разбиение подобрано по реальным сборкам
в локальной окрестности старых границ, не доказано оптимальным.

Диски 2 и 3 сохраняют неизменяемые таблицы банка 6 и фиксированный код,
а также compact n−1 по адресу 6400..72FF. Для изменяемых областей
передаётся список сброса: 13 диапазонов, 2258 байт данных + 54 байта
заголовков, ZX0 **190 байт / один сектор**. Банк 2 A000..BFFF, банк 7
C000..DFFF и первичный экран восстанавливаются обычным способом.
Нативные bitmap обнуляются, первые два кадра последующих томов рисуются
полностью; атрибуты n−2 сохраняются, как в `--cold-bitmaps`.

Кольцо остаётся 64 КиБ; новых постоянных буферов нет. Распакованный
список сброса временно занимает 4000..4907, затем экран загружается заново.
Код применения списка занимает 16 байт внутри прежнего bootstrap.
При холодном запуске диска 2/3 USR возвращается в BASIC с сообщением
`START WITH DISK 1`. Обычный набор и набор с другими опциями имеют другой
идентификатор серии. Версию `WARM1` необходимо менять при изменении
контракта сохранения RAM. Независимый запуск поэтому **не обеспечен**.

## Такты

Горячий путь кадров/AY/дискового чтения побайтно прежний: Δ **0 T**.
Изменён только вход загрузчика следующего тома, `JP nn` остаётся **10 T**.
Применение списка сброса: `21*B + 70*R + 45 T` без вызова,
где B — число копируемых байт, R — число диапазонов. С `LD HL,nn`
10 T и `CALL` 17 T: **48 400 T** для 2258 байт/13 диапазонов.
В прежнем bootstrap этого отдельного прохода не было: **0 → 48 400 T**;
взамен исключены чтение и ZX0-распаковка полных стартовых секций.
Это не полная разница времени запуска: ROM, диск, IRQ и ULA сюда не входят.
Один диапазон 1/257 байт проверен исполнением: **136 / 5512 T** без CALL.
Таблица: [Zilog UM0080](https://www.zilog.com/docs/z80/um0080.pdf).

## Проверка

- Машинный bootstrap с подменённой ROM: два перехода; все изменяемые
  фиксированные области и заменяемые банки предварительно заполнены A7.
  Проверены точный сброс, сохранение compact/таблиц/кода, текст, отказ
  неправильному диску/серии и отказ холодному запуску продолжения.
- Полный Fuse: **4221 кадр, 25 326 точных AY-записей, 6771 точный
  runtime-сектор**, без повторов, все тома доходят до EOF/100% прогресса.
  После каждого EOF экспортированы реальные банки 5/2/6; неизменяемые
  байты и последний compact целиком сверены с исходными.
- Следующий запуск получает эти байты, а не заново построенный checkpoint.
  Остальные пять банков заполнены A5. SZX явно задаёт Spectrum 128;
  PC направлен в старую процедуру ожидания диска. Обе проверки следующего
  идентификатора пройдены, весь следующий том проигран.
- Между томами Fuse и контроллер перезапускаются. Это проверка переноса
  реального состояния RAM, **не** физической замены диска в одном процессе.
  Экран в Fuse сравнивается по 80 байтам на кадр; полной покадровой
  проверки обоих экранов здесь нет.

| Том | Фактическая fps | Пропущено номинальных сроков | Пропущено полей AY | Наибольшее отставание |
|---|---:|---:|---:|---:|
| 1 | 7,9390 | 1560 | 482 | 9,716 с |
| 2 | 7,3785 | 1300 | 1011 | 20,331 с |
| 3 | 7,1830 | 1299 | 1273 | 25,489 с |

Восстановленные поздние серии: 6/0/0; у каждого тома остаётся одна
невосстановленная серия. Ни точные сроки, ни резервные 20 мс не пройдены.
Следовательно, это **не выпуск**, несмотря на выполнение ограничения размера.

## Воспроизведение эксперимента

Пути к входам и исполняемым файлам передаются явно; скрипты не зависят
от конкретного фильма. Команды выполняются из корня рабочей копии с
`PYTHONPATH=toolkit` и доступными numpy/Pillow. Последовательные Fuse
нельзя запускать одновременно с другим измерением Fuse.

```text
python toolkit/probe_warm_continuation.py --raw STREAM.raw --states conversion.npz --zx0 zx0.exe --read-cache CACHE --output WORK --report toolkit/warm_continuation_size.json --ends 1619,2919,4221 --rebalance
python toolkit/test_warm_continuation.py --volumes WORK --states conversion.npz --output toolkit/warm_continuation_swaps.json
python toolkit/measure_warm_continuation.py --volumes WORK --fuse fuse.exe --raw STREAM.raw --states conversion.npz --report toolkit/warm_continuation_fuse.json
python toolkit/archive_warm_continuation.py --source WORK --summary toolkit/warm_continuation_fuse.json --output toolkit/warm_continuation_evidence
```

Формат временного SZX проверен по
[исходнику libspectrum](https://github.com/speccytools/libspectrum/blob/master/szx.c).
SNA не используется: его загрузчик определяет 128-КиБ файл как Pentagon,
что изменило бы исследуемые тайминги. Дамп снимается только после EOF;
перенаправления PC отладчиком не входят в измеренное проигрывание.

Отчёты: [размеры и все границы](warm_continuation_size.json),
[переходы с испорченной RAM](warm_continuation_swaps.json),
[полный Fuse](warm_continuation_fuse.json),
[покадровые свидетельства](warm_continuation_evidence/index.json).

Дальнейшее основное направление: сократить стартовые таблицы и контрольные
кадры, сохранив возможность независимого запуска каждого тома.
