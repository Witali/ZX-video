# Ускорение подготовки полного фильма

Хостовый код повторял подбор 98 палитр для каждого пикселя в каждом из
2–3 вариантов штрафа за смену атрибута. Теперь расстояния считаются один раз
для каждого уникального RGB кадра и используются во всех вариантах. Порядок
кандидатов, выбор при равенстве и формулы ошибки сохранены.

Построение RGB-превью также переведено с циклов Python на индексирование
NumPy: адреса строк ULA, порядок битов, INK/PAPER, BRIGHT и прежняя фиксированная
фаза FLASH те же. Это **не изменение кода Z80**, дельта проигрывателя 0 T.

Старые функции сохранены как `encode_compact_frame_reference` и
`render_spectrum_screen_reference`. Тесты сверяют случайные и одноцветные
кадры, разные штрафы, все 256 значений атрибута/байта bitmap и конечный выбор
режима по ошибке реконструкции. Полученные состояния совпадают побайтно.

В пяти исходных кадрах (0, 60, 200, 400, 590 с) подбор с обратной связью
ускорился в 5,19–27,71 раза. Это локальное время хостового компьютера под
нагрузкой, не ускорение воспроизведения Spectrum. Полные измерения:
`compact_palette_measurements.json`.

```text
python toolkit/benchmark_compact_palette.py --input-video SOURCE.mov --ffmpeg ffmpeg.exe --output toolkit/compact_palette_measurements.json
python -m unittest discover -s toolkit -p test_compact_palette.py
```
