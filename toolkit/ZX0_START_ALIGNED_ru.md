# Полные первые блоки ZX0: начального запаса недостаточно

25 сентября 2026, база `2d2da5e`. Отдельный эксперимент на прежних
4221 кадре и трёх независимых томах, границы 1624/2921/4221.
Разрешение, пиксели, AY, FAP3-пакеты и инструкции проигрывателя прежние.

## Что изменено

Вместо минимального размера выбирается сетка, начинающаяся ровно
с первого байта пакетов тома: смещения **4813 / 335 / 1725**.
Каждый первый блок имеет 8192 распакованных байта. Перед запуском часов
четыре слота содержат **32768 байт** на каждом диске вместо
**27955 / 32433 / 31043** у исходной сетки. Дополнительная RAM не нужна:
те же четыре банка и тот же prefill. Это проверка большего стартового
запаса, а не увеличение ёмкости очереди во время воспроизведения.

Добавлен экспериментальный `--selection start-aligned` к
`build_zx0_block_phase.py`; обычный режим и формат не переключены.
Сводка и верификатор теперь допускают отдельные именованные наборы
доказательств. Старый набор `zx0_block_phase` также проходит проверку.

## Размер и загрузка

| Том | Поток до → после, байт | Логические секторы | Использовано TRD |
|---|---:|---:|---:|
| 1 | 641005 → 640778 | 2504 → 2504 | 2543 → 2543 |
| 2 | 640198 → 640069 | 2501 → 2501 | 2544 → 2544 |
| 3 | 638742 → 639131 | 2496 → 2497 | 2543 → 2543 |

Итого **1919945 → 1919978 байт, +33 байта**. Физически по-прежнему
**7630 секторов**, свободно два. Третий том занял один ранее пустой
сектор interleave, поэтому дополнительное логическое чтение не увеличило
физический размер. Во всех новых раскладках padding=0.

Все исходные TRD пересобраны побайтово перед изменением сетки. Новые
образы восстановили все байты таблиц при холодной загрузке; обе смены
дисков прошли проверки приглашения, чужой серии, неверного номера,
правильного продолжения и его RAM. Эти CPU-проверки используют ROM stub.
Отдельные полные прогоны ниже выполняются с настоящей TR-DOS в Fuse.

## Детерминированный CPU

Проверены все **4221 пакет / 3083375 байт / 378 блоков**. Каждый байт
пакета и последовательность секторов точны; гистограммы инструкций
суммируются с покадровыми и стадийными счётчиками.

| Том | Исходная сетка, T | Полный первый блок, T | Разница, T |
|---|---:|---:|---:|
| 1 | 96151683 | 96219955 | +68272 |
| 2 | 98935478 | 98900547 | −34931 |
| 3 | 103472111 | 103444662 | −27449 |
| Всего | **298559272** | **298565164** | **+5892 (+0,002%)** |

Новых opcodes нет. Суммы включают ZX0, producer, очередь, копирование
пакетов, paging и дисковый адаптер с ROM stub; восстановление кадров,
IRQ, ULA, исполнение TR-DOS ROM и физическое время диска исключены.
Общая CPU-цена почти не изменилась, что не гарантирует прежние сроки
каждого кадра: распределение работы между блоками всё же отличается.

## Полное воспроизведение

Сравнение с `94c2e6f`: та же очередь и compiled masks. Все **4221 кадр,
25326 AY-записей, 7502 runtime-сектора** проверены, retries=0,
progress=100% всех томов. Изображение — 80 адресов на кадр, не новый
полный попиксельный прогон; пакетные байты остаются прежними.

| Том | FPS до → после | Late до → после | AY underrun до → после |
|---|---:|---:|---:|
| 1 | 8,063394 → 8,056190 | 989 → 987 | 326 → 333 |
| 2 | 7,548928 → 7,548049 | 1142 → 1147 | 803 → 804 |
| 3 | 7,393284 → 7,397494 | 1272 → 1264 | 1011 → 1006 |

Publication spans **1945219164 → 1945573704 T**, **+354540 / +0,018%**.
Всего late **3403 → 3398**, AY underrun **2140 → 2143**.
Максимальное опоздание **338/809/1011 полей**, actual OUT deviation
**23966907/57364583/71687988 T**; actual OUT >1 поля на
**987/1147/1264** кадрах. Интервалы вне 5..7 полей ±64 T:
**397/473/519**. Восстановлены **1/2, 0/1, 3/4** серий; последние
серии продолжаются до EOF. Номинальные сроки и резервный допуск провалены.

Чтение секторов **235659555 → 235671756 T**, seek/side
**5186440 → 5193416 T**, включая ROM/IRQ/ULA/контроллер.
Начальные фазы диска и IRQ не выравнивались. Измерение не выделяет
чистую причинность стартового объёма: сетка меняет также все блоки,
стоимость распаковки и моменты обращений к диску.

## Решение

Не включать start-aligned как улучшение по умолчанию. Он заметно лучше
неудачного выбора по минимальным байтам для второго тома, но не лучше
исходного комплекта в целом и не обеспечивает точные 25/3 кадра/с.
Дальнейший перебор начальной сетки не является основным направлением:
нужно уменьшать подготовку тяжёлых кадров или подготавливать их дальше
вперёд. Сжатый поток и степень подготовки данных следует оценивать вместе.

Предварительная проверка свободного места в фиксированной памяти:
максимальные пакеты по томам **2640/2923/3647 байт**, включая двухбайтовую
длину. У третьего тома payload=3645, необходим ещё байт Huffman lookahead.
Из текущего буфера 4704 байта это освобождает только **1058 байт**, меньше
3840 байт второго полного compact-кадра. Это ограничение простого
сокращения одного буфера, не доказательство невозможности иной раскладки
128 КиБ. Следующий кандидат — объединение разбора масок с восстановлением
кадра, чтобы уменьшить промежуточные записи для неизменных участков.

Экспериментальные TRD находятся в `.tmp/three`, корневой выпуск не заменён.
Размер отдельного release-bootstrap очереди/compiled masks не проверен:
Fuse устанавливает runtime после обычного независимого bootstrap.
Проверки физического дисковода нет, цель по срокам пока не достигнута.

## Воспроизведение

Команды из `.worktree/zx0-start-aligned` в PowerShell. Входы и compressor
проверяются по SHA сохранённого полного перебора `zx0_block_phase_probe`;
при новом checkout нужны локальные входы предыдущих экспериментов.

```powershell
$python = 'C:/Users/rudol/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe'
$env:PYTHONPATH = 'toolkit;C:/Work/ZX-video/.worktree/audio-fidelity/.tmp/python_packages'
$env:OPENBLAS_NUM_THREADS = '1'
& $python toolkit/build_zx0_block_phase.py --selection start-aligned `
  --probe toolkit/zx0_block_phase_probe.json `
  --raw-directory ../volume-huffman/.tmp/probe `
  --directory ../register-fragments/.tmp/three `
  --states ../three-disk-quality/.tmp/no_credits/source/conversion.npz `
  --zx0 ../audio-fidelity/.tmp/bin/zx0.exe `
  --output .tmp/three --report toolkit/zx0_start_aligned_build.json `
  --read-cache ../zx0-block-phase/.tmp/probe/zx0 `
  --read-cache ../register-fragments/.tmp/three/zx0 `
  --read-cache ../volume-huffman/.tmp/probe/zx0
& $python toolkit/benchmark_slot_queue.py `
  --directory .tmp/three --output toolkit/zx0_start_aligned_cpu.json
foreach ($part in 1..3) {
  $stem = 'ZX-video-huffman-preview_part{0:00}' -f $part
  $report = '.tmp/fuse/part{0:00}.json' -f $part
  & $python toolkit/measure_fap3_fuse.py `
    --fuse 'C:/Program Files (x86)/Fuse/fuse.exe' `
    --trd ".tmp/three/$stem.trd" --metadata ".tmp/three/$stem.json" `
    --raw "../volume-huffman/.tmp/probe/volume-$part.raw" `
    --states ../three-disk-quality/.tmp/no_credits/source/conversion.npz `
    --output $report --timeout 300 --slot-queue --compiled-masks `
    --fixture-zx0 ../audio-fidelity/.tmp/bin/zx0.exe
  if ($LASTEXITCODE -ne 0) { throw 'Incomplete Fuse run' }
}
& $python toolkit/summarize_zx0_block_phase.py `
  --probe toolkit/zx0_block_phase_probe.json `
  --build toolkit/zx0_start_aligned_build.json `
  --cpu toolkit/zx0_start_aligned_cpu.json --fuse .tmp/fuse `
  --evidence toolkit/zx0_start_aligned_evidence `
  --output toolkit/zx0_start_aligned_summary.json
& $python toolkit/verify_zx0_block_phase.py `
  --summary toolkit/zx0_start_aligned_summary.json
```
