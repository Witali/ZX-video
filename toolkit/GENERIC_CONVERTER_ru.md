# Универсальный конвертер видео → TRD

Измерения 21 сентября, оформление 24 сентября 2026. База плеера — `00313d3`. Точка входа:
[`convert_video.py`](convert_video.py). Пользователь передаёт видеофайл,
конвертер сам готовит кадры, AY, FAP3 и нумерованные дискеты.

## Что делает конвертер

- FFmpeg выбирает основной видеопоток и основную аудиодорожку, если она есть.
  Поддерживаются локальные видео тех форматов/кодеков, которые открывает
  установленная сборка FFmpeg. DRM, URL и поток без конца не поддерживаются.
- Обработка через EOF. Нет сценария монтажа мультфильма, фиксированного
  количества кадров, увеличения 1,25× или обрезания титров. Более длинный
  звук сохраняется с повторением последнего изображения. Финальный интервал
  дополняется до целых 120 мс, короткий однокадровый ролик тоже допустим.
- Изображение вписывается с сохранением display aspect ratio, включая
  неквадратные исходные пиксели. Активная область 256×144, экран 256×192;
  компактные данные 128×96, четыре уровня заполнения 2×2 пикселей, прежняя
  цветовая атрибутная палитра. Чёрные полосы сверху/снизу остаются постоянными.
  Дополнительной адаптации контраста или потерь ради заданного числа дискет нет.
- AY: существующий анализ гармоник, три голоса, шум B при необходимости,
  шесть обновлений на видеокадр. Mono обрабатывается штатно; отсутствие звука
  даёт тишину. Учитывается смещение аудиопотока относительно первого кадра.
- [`encode_fap3.py`](encode_fap3.py) обучает таблицы на переданных кадрах:
  межкадровая дельта, движение, предсказание соседними байтами, Huffman,
  готовые фрагменты, маски изменённых знакомест, затем ZX0. Проверяется
  независимое обратное восстановление всех компактных кадров и AY-записей.
  Пустые Huffman-контексты короткого ролика преобразуются в полные деревья;
  чрезмерный пакет имеет ограниченный вариант из готовых фрагментов.
- Число дискет зависит от фактических ZX0-данных, загрузчика, контрольных
  состояний и физического размещения секторов. Границы не зависят от
  продолжительности конкретного мультфильма. Планировщик оставляет небольшой
  запас; глобальный минимум числа дискет не доказывается.
- Каждая часть загружается самостоятельно. Сохраняются предыдущие кадры и AY
  для продолжения; сообщение `INSERT NEXT DISK`, проверка серии/номера,
  прогресс 0–100% именно текущего диска — прежние.

## Параметры

```powershell
python toolkit/convert_video.py "input.mkv" --output "build/my-video" --prefix MYVIDEO
```

| Параметр | Значение |
|---|---|
| `--ffmpeg`, `--ffprobe`, `--zx0` | Путь к программе; иначе поиск в PATH |
| `--prefix` | Имя файлов, по умолчанию `ZX-video`; ASCII буквы, цифры, `_`, `-` |
| `--max-frames-per-disk` | Дополнительный предел; по умолчанию 4096, диапазон 1…10922 |
| `--disk-profile portable` | Обычные вызовы TR-DOS, профиль по умолчанию |
| `--disk-profile trdos503` | Прямое чтение, cached seek, порядок секторов 1,9,2,10,… |
| `--trdos-rom` | Обязательная проверка ROM для профиля `trdos503` |
| `--inline-matches` | Измеренный вариант ZX0 без CALL/RET на каждое совпадение; поток прежний, выключен по умолчанию |
| `--fast-noop-scan` | Экспериментальная объединённая проверка неизменённых плиток, без копирования векторов; выключена по умолчанию |
| `--verify cpu` | Все кадры, AY и исполненные инструкции с идеальной подачей данных; по умолчанию |
| `--verify fuse --fuse PATH` | Дополнительно полный реальный прогон каждой дискеты в Fuse |
| `--verify none` | Только обратная распаковка на PC; измерение тактов пропускается |
| `--verification-timeout` | Лимит ожидания Fuse на диск, по умолчанию 1800 секунд |

16-битный счётчик AY допускает не более 65535/6 = 10922 кадров на диск.
Заголовок потока и границы серии поддерживают 32-битные номера кадров;
старые короткие серии сохраняют прежний fingerprint. При использовании
`trdos503` нужен ROM SHA-256
`91259fca6a8ded428cc24046f5b48b31d4043f2afbd9087d8946eaf4e10d71a5`.

Выходная папка должна быть новой или пустой. Скрипт не перезаписывает
предыдущий результат. Промежуточные данные находятся в `work/`: исходные
уменьшенные RGB-кадры, компактные состояния, AY, FAP3 и кэш ZX0.
Время, RAM и временное место на PC растут с длительностью ролика;
это офлайн-конвертер, не обработчик видео неограниченной длины.

## Учёт тактов и задержек

Опция `--inline-matches` добавлена 24 сентября 2026. На эталонном потоке
отдельная распаковка ускорилась на 4,16%, но при отложенном чтении выросло
число нарушенных номинальных сроков, поэтому опция не включена автоматически.
Это не обещание 8⅓ fps для любого ролика. [Расчёт, полный Fuse и ограничения](INLINE_ZX0_MATCHES_ru.md).
Все шесть синтетических входов конвертера проверены с этой опцией;
их FAP3 побайтно совпадает с прежними результатами.

[`profile_fap3.py`](profile_fap3.py) сохраняет два разных измерения:

1. **Детерминированная CPU-проверка.** Исполняются реальные инструкции
   декодера, реконструкции, вывода, переключения банков, прогресса и IRQ.
   Учитываются пройденные ветви, число повторений инструкций и AY-записей.
   Все компактные кадры и оба native-экрана сравниваются полностью.
   В `*.cpu.json` есть таблицы инструкций, гистограммы исполнения, суммы
   по этапам, IRQ, ожидание, события подготовки/публикации. Предположение:
   70908 T на поле, **425448 T на шесть полей**. Здесь нет физической
   дискеты, contention ULA, загрузчика и внешнего цикла boot-driver.
   Дисковый адаптер измеряется отдельно по таблицам инструкций, включая paging.
2. **Полный Fuse.** Проверяются все публикации экрана, все AY-записи, байты
   каждого прочитанного runtime-сектора и 80 байтов экрана на каждый кадр.
   Измеряются интервалы вызовов чтения и seek, весь bootstrap начиная со
   входа в PLAYER, и весь playback до EOF. Это реальное прошедшее время
   с ROM, диском, IRQ и ULA; загрузка PLAYER из BASIC и ожидание пользователя
   между дискетами вне этого интервала. Реальный физический привод не измерялся.

Время ROM и эмулируемого диска внутри вызова записывается совместно:
разделить его на «чистую механику» и инструкции ROM эти точки измерения
не позволяют. Суммы CPU и Fuse **не складываются**: у них разное расписание.
Таким образом, полный Fuse учитывает все задержки от входа в PLAYER до EOF,
а CPU-отчёт объясняет стоимость собственных алгоритмов.

`timing.json` содержит все пропуски номинальных сроков, максимальное
отставание, серии опозданий и их восстановление, реальные интервалы кадров
и нарушения AY 50 Гц. Индексы кадров в каждом дисковом отчёте начинаются с 0.
Проверка допуска 20 мс отдельная; неполный прогон не проходит ни один критерий.
Для микрофазы инструкции OUT используется прежний допуск 64 T внутри IRQ;
он не скрывает пропущенное поле длительностью 70908 T.

Повторная проверка готовой сборки:

```powershell
python toolkit/profile_fap3.py --build "build/my-video" --zx0 "C:/Tools/zx0.exe" --fuse "C:/Program Files (x86)/Fuse/fuse.exe"
```

Код горячего пути плеера прежний, изменение **0 T** относительно `00313d3`.
Изменён только случай короткого bootstrap: переход за область, которую он
перезаписывает дисковым адаптером, — `JP nn`, **10 T**. Раньше такой короткий
поток отвергался сборщиком; большой bootstrap генерирует прежние инструкции.
Режим регистрации AY-underrun изменяет только тестовый интерпретатор:
позволяет досчитать неуспешный по времени ролик до EOF, не скрывая нарушения.

## Результаты и воспроизведение проверок

Основной отчёт: [`generic_converter_checks.json`](generic_converter_checks.json).
Входы генерирует [`check_generic_converter.py`](check_generic_converter.py):
короткий MP4 без звука, вертикальный MKV, AVI с mono-звуком и тремя дискетами,
MOV с SAR 2:1, звук длиннее изображения и случайный видеошум.

```powershell
$env:PYTHONPATH="toolkit"
python -m unittest test_generic_converter test_fap3_disk test_pipelined_frame -v
python toolkit/check_generic_converter.py --output .tmp/generic-check --report toolkit/generic_converter_checks.json --fuse "C:/Program Files (x86)/Fuse/fuse.exe" --trdos-rom "C:/Program Files (x86)/Fuse/roms/trdos.rom"
```

Проверка большего ролика и автоматического деления по вместимости:

```powershell
python toolkit/check_generic_converter.py --only-noise --noise-frames 384 --output .tmp/generic-capacity --report toolkit/generic_converter_capacity.json --fuse "C:/Program Files (x86)/Fuse/fuse.exe" --trdos-rom "C:/Program Files (x86)/Fuse/roms/trdos.rom"
```

Готовые TRD — экспериментальные. Корневые образы мультфильма этот инструмент
не заменяет. `conversion.json: complete=true` означает успешную конвертацию,
`timing_verified=true` — выполнение номинальных сроков и AY 50 Гц в полном
Fuse-прогоне всех частей. Сложное видео может не пройти второй критерий.
`video-quality.json` сохраняет ошибку каждого кадра после перевода в палитру
Spectrum; `video-preview.png` — исходник и результат для первого, последнего
и кадров с наибольшей ошибкой; `audio-quality.json` — сравнение синтеза с исходным звуком.
Эти метрики не являются процентом субъективного сходства.
