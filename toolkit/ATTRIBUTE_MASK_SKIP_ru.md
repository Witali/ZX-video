# Пропуск пустых групп при реконструкции атрибутов

20 сентября 2026. База `6dbb142`, полный FAP3 без титров, **4221 кадр**,
те же исходные состояния и AY 50 Гц, **1932429 байт** с ZX0 и заголовками.

**Результат:** реальная реконструкция атрибутов на всех кадрах требует
**20201726 вместо 38721106 T**, экономия **18519380 T / 47,83% этой стадии**.
Сюда включён атрибутный Huffman. Весь проигрыватель не стал быстрее на
47,83%. Поток не меняется; добавлено **0 байт и 0 секторов** данных.

## Изменение

Прежний код проверяет все 96 восьмибитовых масок, в том числе пустые.
Декодер метаданных уже оставляет 12 флагов: каждый указывает, какие из
восьми следующих масок непусты. Новый контроллер использует эти флаги.
Нулевой флаг пропускает восемь масок и 64 атрибута целиком; ненулевой
вызывает прежнее применение восьмибитовой маски только там, где нужно.

Реконструкция остаётся относительно предыдущего compact-состояния n−1.
Списки вывода для экранов n−2 работают отдельно и не изменены. Порядок
Huffman-символов и указатели битов/литералов сохраняются. Абсолютные
атрибуты идут прежним путём LDIR. Контроллер учитывает все 96 масок,
включая края, и не опирается на предположение, что они всегда пусты.

Опция `--attribute-flags` включает новый путь. По умолчанию остаётся
предыдущая генерация кода. Без разборщика метаданных опция отклоняется.

## Такты Z80

Источник времён инструкций — [Zilog UM0080](https://www.zilog.com/docs/z80/um0080.pdf).
В отчёте сохранены машинный код, инструкции и фактические гистограммы.
Каждая исполненная инструкция проверяется по таблице.

| Стадия | Прежде, T | Теперь, T | Разность |
|---|---:|---:|---:|
| Обход масок и применение атрибутов | 34392554 | 15873174 | −18519380 |
| Атрибутный Huffman | 4328552 | 4328552 | 0 |
| **Всего** | **38721106** | **20201726** | **−18519380** |

Для кодированного кадра точная разность к базе:

`−5551 + 530 × F + 50 × G`,

где F — число непустых флагов из 12, G — число непустых масок из 96.
Для raw-кадра разность равна нулю. Формула сверена на всех кадрах и
искусственных комбинациях; стоимость неизменённого Huffman сокращается
при вычитании. Все переходы через страницы также учтены:

- Прежняя пустая маска: 75 T, на границе страницы 74 T.
- Прежняя непустая маска: `240 + 47 × K + H` T.
- Новый пустой блок из восьми масок: 136 T, на границе страницы 135 T.
- Новый непустой блок: `666 + 215 × G + 47 × K + H` T;
  вычесть 1 T, если последняя маска пуста и заканчивается страница.
- Setup/выход, включая raw-проверку: 81 T прежде, 98 T теперь.

K — число исправляемых атрибутов, H — сумма вызванных Huffman-примитивов
без внешних CALL. При всех пустых масках: **7278 → 1727 T**.
На **100 кадрах** новый путь дороже; максимум **1799 T** на кадре 3686.
Средняя экономия не означает ускорение каждого кадра.

IRQ, ULA, ROM, физический диск, разбор пакетов, bitmap-реконструкция и
native-вывод в таблицу не включены. Общий прогон описан отдельно ниже.

## Память

- Основной код реконструкции: **4081 → 4052 байта**, конец **8FF1 → 8FD4**.
- Новый контроллер: **9360h..93A6h**, **71 байт**, состояние не требуется.
- Чистый прирост фиксированного кода — **42 байта**. Renderer с atomic
  paging и списками атрибутов заканчивается на **9355h**: до контроллера
  11 байт. После контроллера до AY 9400h остаётся 89 байт.
- Прежние 128 КиБ распределены так же: экраны 5/7, fixed code и compact
  в 5/2, Huffman в 6, дисковое кольцо 0/1/3/4 и ZX0-history в 7.
  Области стека, AY, TR-DOS workspace, таблиц и кадров не перемещались.
  Дополнительного кольца или кадрового буфера нет; дисковый буфер не уменьшен.

Сборка проверяет пересечение контроллера с renderer и AY. Записи в код,
таблицы, входной поток и чужие области ловятся защитой CPU-стенда.

## Проверка

Полный измеритель стадии независимо сверяет исходный Huffman-хвост
атрибутов с предыдущим/текущим состоянием. Затем обе версии исполняют
исходные биты/литералы на Z80 начиная с точного битового смещения после
bitmap. На каждом из 4221 кадров совпали все 768 атрибутов, конечные
позиции масок, битов и литералов; bitmap/cache/native-области не изменены.
Это не исполнение всей bitmap-реконструкции на 4221 кадре.

Три новых теста проходят:

1. Все 256 рисунков каждого из 12 флагов, позиции битов, границы страниц,
   все маски FF и абсолютные атрибуты; формула сравнивается с прежним Z80.
2. Четыре составных кадра в общем pipeline: настоящая реконструкция,
   два native-экрана и точная разность полного CPU.
3. Настоящий AY IRQ после каждой инструкции sparse/full/raw-путей,
   включая 18-битовые Huffman-коды с начальным смещением 7 бит. Регистры,
   paging, стек и AY сохраняются; число IRQ сверено с числом инструкций.

Также прошли пять прежних проверок атрибутных списков и холодного старта.
Тест с IRQ после каждой инструкции проверяет сохранность состояния, а не
равномерный темп 50 Гц. Темп проверяется следующим отдельным запуском.

## Общий проигрыватель: прогон остановился на недогрузке AY

Запрошены все 4221 кадр; настоящие IRQ каждые 70908 T, lookahead,
idle-предвыборка пакетов, ускоренные копии и прежние списки вывода.
Дисковый источник идеальный, ULA/ROM/физическая подача не моделируются.

| Проверка | База | Новый путь |
|---|---:|---:|
| Compact/native/пакетов/публикаций | 416 каждого | **623 каждого** |
| Точных AY ticks до остановки | 2496 | **3738** |
| Первый поздний кадр, индекс от 0 | 411 | 411 |
| Поздних на общем префиксе 416 публикаций | 5 | 5 |
| Максимум опоздания на общем префиксе | 5 полей | 5 полей |
| Фаза фактического OUT у своевременных по счётчику кадров | −16..59 T | −13..30 T |

За весь новый проверенный фрагмент: **19 пропущенных номинальных сроков**,
максимум 5 полей. 15 кадров вышли за резерв в одно поле; по фактическому
OUT превышений 20 мс — 16 (один кадр поздний на 70909 T вместо 70908).
По счётчикам есть один интервал 4 поля и три по 8; по точным OUT два
интервала ниже 5 полей и шесть выше 7. Оба критерия плавности нарушены.

Серии 411..422 и 576..579 вернулись к исходным срокам на кадрах 423 и
580. Серия 620..622 не восстановилась до остановки. Все отдельные
опоздания с точными T сохранены в [сводке](attribute_masks_summary.json).
Ранних публикаций относительно исходных номинальных полей нет.

Ошибка — `scheduled AY underrun, 3738`, CPU остановлен на 266443936 T.
Foreground до разных остановок: 131178791/202321384 T, IRQ отдельно
2162960/3268010 T. Эти суммы относятся к разным объёмам работы и не
используются для вычисления ускорения всего проигрывателя.

**Решение:** сохранить опцию для следующих общих сравнений. Выигрыш
полной стадии подтверждён, исходные данные не растут. Сборку трёх TRD
и полное расписание 120 мс этот частичный прогон не подтверждает; новых
релизных дисков нет. Следующая работа — дорогая реконструкция bitmap и
подготовка данных тяжёлых сцен, с сохранением ограничений по общему CPU
и дисковому потоку. Векторный эксперимент остаётся отдельным направлением.

## Воспроизведение

Исходные `$raw`, `$states`, `$cache` — тот же поток FAP3 и его optimal ZX0
кэш из [предыдущего опыта](ATTRIBUTE_GROUPS_ru.md). `PYTHONPATH` содержит
`toolkit` и пакеты проекта. Скрипты и отчёты сохранены в репозитории.

```powershell
python -m unittest toolkit.test_attribute_masks
python toolkit/benchmark_attribute_masks.py --raw $raw --states $states --output toolkit/attribute_masks_cpu.json
python toolkit/benchmark_pipelined_frame.py --raw $raw --states $states --storage-report toolkit/lean_frame_zx0.json --cache $cache --output toolkit/attribute_masks_idle_cpu.json --lookahead --packet-ahead --packet-ahead-policy idle --unrolled-copy --unrolled-cache --attribute-groups --attribute-flags
python toolkit/summarize_attribute_masks.py --cpu toolkit/attribute_masks_cpu.json --before toolkit/attribute_groups_idle_cpu.json --after toolkit/attribute_masks_idle_cpu.json --output toolkit/attribute_masks_summary.json
```

Третий вызов завершается ошибкой AY, сохраняя частичный отрицательный
результат. Это ожидаемый результат данного опыта, а не успешный release check.
