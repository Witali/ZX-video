# Совпадение границ видео с сеткой знакомест

19 сентября 2026. Проверка предложения масштабировать видео так, чтобы
его внешние границы совпали с сеткой Spectrum и не требовали обработки
неполных знакомест. База — `1962628`, 4221 кадр без титров, прежний age3.
Сам ролик не масштабировался, данные и Z80-код этой проверкой не менялись.

## Что уже делает код

В [конвертере](build_long_video_trd.py) логическая картинка 128×72
помещается в строки 12..83 полотна 128×96 (`ACTIVE_Y0=12`,
`ACTIVE_HEIGHT=72`). Расширение 2×2 даёт **256×144** на экране 256×192:

| Граница | Координата, правая/нижняя исключены | Кратна 8 |
|---|---:|---|
| Левая | 0 | Да |
| Правая | 256 | Да |
| Верхняя | 24 | Да |
| Нижняя | 168 | Да |

Таким образом, границы исходной активной картинки **уже выровнены**.
В [native renderer](cell_screen_z80.py) `draw_cell` записывает целое
знакоместо 8×8. `partial_cells` означает разреженное множество целых
знакомест в полосе, а не обрезку знакоместа по внешней границе ролика.
Такое множество остаётся при движении объектов внутри изображения.

Восстановление compact frame использует другой блок: 8×8 логических
пикселей, то есть 16×16 экранных. Его верхняя/нижняя граница 24/168
пересекает половину блока. Выравнивание по этой сетке потребовало бы
изменить геометрию или отдельно обрабатывать постоянное обрамление;
оно не устраняет разреженные изменения внутри движущейся сцены.

## Полный аудит состояний

[Отчёт](video_cell_alignment.json) проверил все 4221 кадр. За пределами
номинальной картинки сохранены **440 ненулевых compact-байтов**, всего
**488 ненулевых логических пикселей**, в **269 кадрах**, первый — 25.
Они находятся в логических строках 8..11 и 84..87. Это объясняет,
почему текущий точный вывод захватывает 20 полос вместо 18: нельзя
просто перестать выводить эти данные и продолжать заявлять побитовое
совпадение с принятым age3.

Полезная следующая проверка — сделать эти внешние поля строго чёрными
и ограничить вывод 18 полосами, сохранив масштаб и всю активную картинку.
Это изменит указанные пиксели полей; требуется отдельно показать
покадровую разницу, измерить реальные такты и расписание. **Экономия
размера/CPU этой идеи пока не измерена.** Само масштабирование ради
выравнивания по 8×8 для текущей геометрии не требуется.

```powershell
python toolkit/audit_video_cell_alignment.py --states .tmp/no_credits/source/conversion.npz --output toolkit/video_cell_alignment.json
```
