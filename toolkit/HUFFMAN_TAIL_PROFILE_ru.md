# Четырёхбитные таблицы длинных кодов: профиль памяти

18 сентября 2026. База `15b5638`, лучший FHS1 и все 4971 кадр age3.
Цель — ускорить длинные коды Хаффмана без увеличения видеопотока.
Это исследование таблиц, а не новый машинный декодер.

В существующем потоке 1473262 значения, из них **137055** имеют длину
больше восьми бит. Максимальная длина — 17. После первых восьми бит
канонический декодер выполняет **292272** отдельных шага чтения бита.
Обработка по четыре бита потребовала бы **145190** обращений к узлам,
но это не измерение тактов: адресация и получение следующих битов тоже
стоят времени.

Полные таблицы из 16 вариантов на узел, с объединением одинаковых
поддеревьев всех 17 контекстов, требуют **736 уникальных узлов**.
Первых длинных префиксов — 407. По 16 значений и 16 длин — 23552 байта,
корневые таблицы — 8704, таблицы сдвигов — 4096. Сумма **36352 байта**
превышает один 16-КиБ банк на 19968, ещё без адресных таблиц 1472 байта.
Прежнее тело таблиц занимает 12112 байт без сдвигов, то есть 16208 с ними.

Это предварительная оценка размещения: идентификаторы 736 узлов уже
не помещаются в байт. Для указанного размера пришлось бы упаковать
старшие биты идентификатора в свободные биты поля длины; машинная
реализация, адресация и переключения банков не разработаны.
Никакое уменьшение дискового буфера этим опытом не принимается.

Проверен также ограниченный вариант: ускорять только наиболее частые
первые узлы и только листья длин 9..12. Более длинные коды продолжали
бы пользоваться прежним декодером. Совпадающие частичные таблицы
объединены, ранжирование — по фактическому использованию во всём фильме.

| Таблиц | Только данные таблиц, байт | Значений, попадающих в быстрые листья |
|---:|---:|---:|
| 16 | 512 | 11798 |
| 32 | 1024 | 21553 |
| 64 | 2048 | 37657 |
| 128 | 4096 | 64564 |

Адресные таблицы, перенаправление корней, диспетчеризация и стоимость
возврата к каноническому декодеру здесь не учтены. Поэтому эти числа
не подтверждают выигрыш общего времени кадра. Размер видеоданных
не измерялся заново: сам поток не менялся.

**Проверка:** скрипт построил канонические деревья и независимо прошёл
все длинные коды и варианты хвостового дополнения через новые таблицы.
Частоты собраны по полным исходным состояниям и поправкам и согласуются
с прежним числом длинных ветвей CPU. Состояния SHA
`4b9e90d22df2809a70c1cb09890de0a9bb0a23d1b1e357b3f6c29ff830cc9c3b`.

**Решение:** полный вариант не переносить в текущую карту одного банка.
Частичный оставить возможным опытом после оценки свободной RAM и
точных Z80-тактов. Плеер/TRD не менялись; изменение горячего пути **0 T**.
