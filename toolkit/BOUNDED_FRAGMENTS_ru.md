# Ограниченное упрощение фрагментов: небольшой выигрыш после ZX0

24 сентября 2026, база `3e0db88`. **Офлайн-опыт, не выпуск.**

## Результат и решение

Упрощение только существующих 16-байтовых литералов уменьшило полный
пакетный ZX0-поток **1 929 729 → 1 926 189 байт**, на **3540 байт,
0,1834%**. Применение того же поиска ко всем сложным блокам увеличило
поток до **1 976 621 байта**, +46 892. Ни один результат не подтверждает
три рабочие дискеты или своевременный вывод всех кадров.

Оба варианта сохранены для воспроизведения, но фильтр не включён в общий
конвертер. Пиксельные изменения допустимы по прежним численным ограничениям;
выигрыш слишком мал, чтобы ради него сейчас менять основной видеоряд.
При этом более компактная команда двух строк **дороже для CPU**, чем
прямое копирование 16 байтов. Следующий выбор должен учитывать соседние
кадры, реальный ZX0 и стоимость всех стадий, а не только размер литерала.

## Вход и границы качества

- Весь монтаж [movie_no_credits.json](movie_no_credits.json): 4221 кадр,
  сохранены история и сцена после титров, исходные индексы кадров в NPZ.
- Текущий FAP3: SHA-256
  `1aff3a304635025c25cc8b20d066b6044f2767b02c99d2490c9f9ae1613ac2ab`.
- Текущие компактные кадры: SHA-256
  `fdabc3331ee2ce7da23a5aa0dd3e2574e4bf7bf84d07abe381c5cecd7bc1e791`.
- Эталон до разрешённых малозаметных изменений: прежнее Spectrum-видео,
  полный источник SHA-256
  `9cc006a31408e2c3c3f96f96901b003756c2a480497e12d6b124baedafaeb35d`;
  после применения монтажных индексов —
  `e89fc674562bc7fe4c05f8e8568dbcfd455cf1075f6a6df9c74c1e6e4cfb59d4`.
- Разрешение, число кадров, все байты атрибутов и 25 326 AY-записей
  неизменны. Это сохранение AY-данных, не новая проверка физических 50 Гц.
- Ошибка каждого выходного кадра считается **от исходного эталона**,
  включая ранее внесённые изменения: максимум два логических пикселя
  на физическое знакоместо 8×8, один шаг четверти заполнения на пиксель,
  RMSE усреднённого RGB знакоместа ≤24, максимум 128 точек на кадр.
- Непрерывная ошибка знакоместа ограничена тремя кадрами. При заполненном
  бюджете часть старых приближений возвращается к исходнику. Ошибка нового
  фильтра не добавляется поверх старого бюджета. Монтажный разрыв сбрасывает
  счётчик; в потоке остаётся прежний независимый старт сцены после титров.

## Поиск и кодирование

Для блока 8×8 логических пикселей рассматриваются 36 пар из его восьми
строк, включая одинаковые пары. Каждая исходная строка заменяется ближайшей
из двух; при равной ошибке предпочтение сохраняющему текущую строку варианту.
Проверяются ограничения каждого из четырёх знакомест блока. Из допустимых
вариантов выбирается более короткая команда, затем меньшая ошибка.

Два опыта:

1. **Все сложные блоки:** 35 519 выбранных упрощений, включая блоки,
   которые на диске представлены движением или поправками Huffman.
2. **Только raw-фрагменты:** 2321 упрощение, разрешены только позиции,
   где текущий поток использует режим 85 — 16 готовых байтов.

Пересборщик оставляет прежние таблицы Huffman и векторы движения;
пересчитывает поправки относительно **действительно изменённых** предыдущего
и текущего кадров. Старые целые фрагменты сохраняются как целые фрагменты,
но допускают более короткие режимы 86/87/88. У остальных блоков простая
команда выбирается, если её битовая цена не выше масок и кодов поправок.
Это совместный опыт фильтра и такого локального выбора команд.

Карта вывода дополняется новыми изменениями относительно кадра n−2;
безвредные прежние отметки сохраняются. Покрытие кэша движения остаётся
достаточным: новые векторы движения не вводятся. Отсутствующий символ Huffman
может уйти в готовый литерал; в обоих полных опытах таких случаев **0**.

Перед каждым опытом пересборка старых кадров без нового выбора команд
должна побайтно воспроизвести исходный FAP3. Оба контроля прошли.
Затем независимый причинный декодер восстанавливает весь новый видеоряд
и сверяет AY. Сам поиск не является глобальной оптимизацией потока.

## Объём

| Вариант | Исходный FAP3, байт | ZX0 с заголовками, байт | Δ ZX0 | Секторы общего потока |
|---|---:|---:|---:|---:|
| База | 3 097 959 | 1 929 729 | 0 | 7539 |
| Все сложные блоки | 3 122 287 | 1 976 621 | +46 892 | 7722 |
| Только raw-фрагменты | 3 075 060 | 1 926 189 | −3540 | 7525 |

Оптимальный ZX0 v2, блоки до 8192 байт с границами как в `Builder.stream`;
исходный заголовок таблиц не включается в видеопоток. Каждый блок проверен
независимой распаковкой, включая повторно использованные блоки кэша.
Не включены загрузчик, разбиение на тома, checkpoint и interleave.
**7539/7525 секторов — не число секторов готового комплекта TRD.**

| Изменение несжатых частей FAP3 | Все блоки | Только raw |
|---|---:|---:|
| Литералы bitmap | −16 141 | −26 461 |
| Маски | +19 691 | +1396 |
| Коды Huffman | +20 778 | +2166 |
| Остальные части, в том числе AY | 0 | 0 |
| Сумма | +24 328 | −22 899 |

Упрощение текущего кадра меняет предсказание последующих. Возврат точного
знакоместа после трёх неточных кадров также требует поправок. Это объясняет,
почему сумма сокращений самостоятельных 16-байтовых фрагментов не равна
выигрышу фильма. Вторая потеря возникает во внешнем ZX0: повторения строк
уже частично сжимались в исходных литералах.

## Такты и память

Нового кода Z80 нет: изменение инструкций горячего пути **0 T**, новых
буферов и таблиц **0 байтов**. Прежняя раскладка всех 128 КиБ сохраняется.
Но количество выполняемых команд меняется вместе с данными.

По ранее проверенной таблице инструкций `causal_tile_z80.fast_tstates`
для режима с отдельными литералами, включая RET и внутренний диспетчер,
без внешнего CALL, IRQ/ULA/ROM/диска:

| Режим | T на тело | Δ относительно raw 85 |
|---|---:|---:|
| 85, 16 готовых байтов | 492 | 0 |
| 86, одна двухбайтовая строка | 487 | −5 |
| 87, выбор двух строк | 774..834 | +282..342 |
| 88, один повторяющийся байт | 459 | −33 |

Для **61 862 общих целых фрагментов** сумма тел в базе **31 931 046 T**
(совпадает с прежним полным CPU-профилем), после широкого фильтра
**32 538 063 T, +607 017**, после raw-фильтра **32 547 284 T, +616 238**.
Это покомандная проекция на новые payload/selector, **не исполнение нового
полного проигрывателя**. В неё не входят новые целые фрагменты на месте
Huffman, изменения масок/кэша/вывода/ZX0 и дисковой нагрузки. Нельзя объявлять
эту разность ни полным замедлением, ни ускорением всего видео.

Полные CPU/Fuse-прогоны новых потоков не выполнялись. Широкий опыт проиграл
по объёму, а экономия узкого слишком мала для продвижения его в выпуск.
Новые TRD не собраны; точные сроки, резервные 20 мс и AY 50 Гц для этих
потоков **не подтверждены**.

## Проверки, файлы и воспроизведение

Четыре теста проверяют запрет перехода на две четверти яркости, ограничения
знакоместа/кадра, принудительное восстановление после трёх кадров, общий
бюджет старых и новых ошибок, неизменность атрибутов и исключённых блоков.
Оба потока полностью независимо декодированы: **8442 кадра и 50 652
AY-записи**, дополнительно два побайтных контроля исходного FAP3.
Качество посчитано для базы и обоих вариантов, всего 12 663 кадра.

```powershell
$env:PYTHONPATH='toolkit'
$original='C:/Work/ZX-video/.worktree/audio-fidelity/toolkit/build_full_movie/source/conversion.npz'
$baseline='C:/Work/ZX-video/.worktree/three-disk-quality/.tmp/no_credits/source/conversion.npz'
$raw='C:/Work/ZX-video/.worktree/three-disk-quality/.tmp/lean_frame/stream.raw'
$zx0='C:/Work/ZX-video/.worktree/audio-fidelity/.tmp/bin/zx0.exe'
$cache='C:/Work/ZX-video/.worktree/three-disk-quality/.tmp/lean_frame/zx0/optimal'
python toolkit/probe_bounded_fragments.py --reference $original --baseline $baseline --raw-fragments-of $raw --output .tmp/row_pairs_raw_only.npz --report toolkit/bounded_fragments_raw_only_selection.json
python toolkit/reencode_bounded_fragments.py --source $raw --baseline $baseline --candidate .tmp/row_pairs_raw_only.npz --output .tmp/row_pairs_raw_only.raw --report toolkit/bounded_fragments_raw_only_stream.json
python toolkit/measure_bounded_fragments.py --source $raw --candidate .tmp/row_pairs_raw_only.raw --zx0 $zx0 --cache .tmp/zx0 --read-cache $cache --output toolkit/bounded_fragments_raw_only_zx0.json
python toolkit/review_bounded_fragments.py --reference $original --candidate .tmp/row_pairs_raw_only.npz --output toolkit/bounded_fragments_raw_only_quality.json --filmstrip toolkit/bounded_fragments_raw_only_quality.png

```

Для широкого опыта убрать `--raw-fragments-of`, заменить `row_pairs_raw_only`
на `row_pairs`, а префикс отчётов — на `bounded_fragments`.
Для проверки качества базы передать её NPZ в `--candidate`.
Исходные файлы и старые кэши читаются без изменения.
