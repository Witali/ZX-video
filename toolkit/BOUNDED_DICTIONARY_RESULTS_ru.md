# Словарь с ограниченной ошибкой изображения

Дата: 18 сентября 2026. База: `24a819a`; выпуск дисков остаётся `69754f3`.
**Статус: завершённый офлайн-опыт, цель трёх дискет ещё не достигнута.**

## Условия пользователя

Весь мультфильм должен помещаться не более чем на трёх дискетах.
Разрешение и 25/3 кадра/с сохраняются, AY остаётся прежним на 50 Гц.
На уточнение о допустимых потерях пользователь ответил:
«Только малозаметные изменения пикселей».

Текущее видео уже использует **четыре значения на логический пиксель**,
то есть 2 бита. В `build_player_dither_tables()` это узоры 2×2 с заполнением
INK 0%, 25%, 50% и 100%. INK/PAPER задаются отдельно на ячейку 8×8,
поэтому это не глобальная четырёхцветная палитра. Логическая сетка 128×96
и физический экран 256×192 в опыте не изменяются.

## Новый формат и ограничения

В отличие от предыдущего [точного словаря](EXACT_DICTIONARY_RESULTS_ru.md),
словарь содержит **только рисунок** ячейки: 4 компактных байта.
Атрибуты передаются отдельно и сохраняются побайтно. Это позволяет одному
рисунку обслуживать несколько цветовых комбинаций. Предсказание n−2
соответствует истории заднего экрана; группы сбрасывают оба предиктора.

ПК ищет ближайший рисунок по квадрату разницы заполнения 16 логических
пикселей ячейки. Похожий рисунок используется только внутри заданных
ограничений; остальные передаются буквально. Никакого поиска на Z80
не предусматривается. Команды: skip n−2, индекс, литералы; затем маска
изменений атрибутов и их значения. Таблица обновляется раз в 512 кадров.

Основная серия ограничивает замену двумя логическими пикселями в ячейке,
каждый — не более чем на четверть заполнения 2×2. Дополнительно ограничен
RMSE цвета, усреднённого по 2×2. Это **критерий отбора**, не утверждение,
что любой проходящий его кадр визуально приемлем. Все результаты затем
сравниваются с принятым Spectrum-изображением.

Проверены 18 вариантов: словари 64/256/1024 записей, пределы RMSE
0/4/8/12/16/24/32 в разных сериях, максимум 2/4/8 изменённых логических
пикселей. Значение 0 — контроль без потерь. Цвета, размер кадра и число
кадров не менялись ни в одной серии. Результат каждого потока независимо
декодирован и побайтно сравнен с выбранными кадрами.

## Объём

Полный фильм: 4971 кадр. Основное сравнение — 256 рисунков, максимум
2 изменённых пикселя, группы 512 кадров, ZX0 v2 **quick**, блоки 6144 байта.
Таблицы, атрибуты, команды и 4-байтовые заголовки ZX0 включены.

| Вариант | Сырой поток | ZX0 с заголовками |
|---|---:|---:|
| Без потерь, RMSE 0 | 4962563 | 3260255 |
| Ограниченная ошибка, RMSE 24 | 4464503 | **3000927** |

Выигрыш: **259328 байт, 7,95%** относительно контроля того же нового
формата. Это не сравнение скорости с текущим PLAYER и не уменьшение
числа готовых TRD. Оптимальный режим ZX0 в этой серии не измерялся.

Звук, загрузчик, новый Z80-код и дисковое округление в эти числа не входят.
Прежний ориентир вместимости трёх TRD — 1937664 байта до дополнительных
расходов. Одно видео превышает его на **1063263 байта**. Перенос формата
в PLAYER сейчас не решит задачу вместимости.

DEFLATE использовался только для отбора. Основной кандидат дал 2872210
байт при блоках 6144; более грубый вариант (256 рисунков, максимум 8
изменений, RMSE 32) дал 2658994 байта. Последний меняет в среднем 0,408%
физических пикселей активной области, в худшем кадре — 1,465%.
Он не принят: полного визуального/временного контроля нет, даже этот
ориентир размера выше бюджета. Серии с 4/8 изменениями сохранены как
проверенные по хранению, но не одобренные по качеству.

## Качество основного кандидата

Измеряется относительно **текущего принятого Spectrum-видео**, а не
исходного HD-фильма. Чёрные полосы исключены: область сравнения 256×144.
SSIM не следует читать как «процент качества».

| Показатель | Результат |
|---|---:|
| Средняя доля изменённых физических RGB-пикселей | 0,164755% |
| Максимум этой доли на одном кадре | 0,482856% |
| Средний SSIM яркости | 0,992374 |
| Минимальный SSIM кадра | 0,966330 |
| 1-й процентиль SSIM | 0,979478 |
| PSNR RGB после усреднения 2×2, весь фильм / худший кадр | 34,198 / 29,609 дБ |
| PSNR физических RGB-пикселей, весь фильм / худший кадр | 28,178 / 23,589 дБ |
| Добавленные полностью повторённые кадры | 0 |

SSIM: окно 11×11, Gaussian σ=1,5, population covariance, C1=(0,01×255)²,
C2=(0,03×255)², среднее по центрам полного окна. RGB→яркость:
0,299R + 0,587G + 0,114B. У кадров без ошибок PSNR в JSON равен null
(бесконечный PSNR), а не нулю.

Визуально просмотрен контактный лист шести худших по SSIM кадров:
643, 4361, 2508, 4267, 2511, 2512. Различия выглядят как редкие точки
дизеринга; крупные формы и цвета сохранены. Это просмотр статичных кадров.
Полная проверка движения ещё не выполнена: отсутствие новых целиком
повторённых кадров не доказывает отсутствие локальных замираний.

## Проверки и память

- Все 18 потоков восстановили ожидаемые 4971 кадр; контроль RMSE 0
  сохранил исходный SHA-256
  `9cc006a31408e2c3c3f96f96901b003756c2a480497e12d6b124baedafaeb35d`.
- Все 1535 блоков двух ZX0-опытов независимо распакованы и сравнены.
- Шесть тестов прошли: n−2 и раскладка ячеек, границы ошибки, соответствие
  RGB-ошибки настоящему рендеру, расширенный индекс/атрибуты, ошибки потока,
  SSIM одинаковых/однотонных изображений с известным результатом.
- SSIM рассчитан для всех 4971 кадров основного кандидата.
- 256 рисунков требуют 1024 байта компактно или 2048 развёрнуто;
  1024 — 4096/8192 байта. Это не требует автоматически отдавать целый банк
  кольца; размещение будущего декодера ещё не выбиралось.
- PLAYER и TRD не менялись, **изменение горячего пути 0 T**. Новые CPU
  T-states, IRQ-сроки, полная доставка с диска и Fuse здесь не измерялись.

## Решение

Сохранить ограниченное квантование как доступный приём, но не выпускать
этот формат: трёх дискет он не достигает. Не усиливать потери только ради
числа дискет. Следующий опыт должен уменьшать остаток: сравнить точные
поправки относительно словаря, предсказание движения и раздельное кодирование
масок/значений. Любой кандидат проверять с тем же исходным хешем, всеми
кадрами и звуком; перед выпуском требуется Z80/Fuse и проверка движения.

## Воспроизведение

`CHECKPOINT` — `source/conversion.npz` принятого полного фильма;
`ZX0` — путь к компрессору ZX0 v2. Кэши не включены в Git.

```text
python toolkit/probe_bounded_dictionary.py --checkpoint CHECKPOINT --output toolkit/bounded_dictionary_measurements.json --cache .tmp/bounded_dictionary
python toolkit/probe_bounded_dictionary.py --checkpoint CHECKPOINT --output toolkit/bounded_dictionary_wider_measurements.json --cache .tmp/bounded_dictionary --limits 16 24 32
python toolkit/probe_bounded_dictionary.py --checkpoint CHECKPOINT --output toolkit/bounded_dictionary_changes4_measurements.json --cache .tmp/bounded_dictionary --limits 32 --entries 64 256 --max-changed-pixels 4
python toolkit/probe_bounded_dictionary.py --checkpoint CHECKPOINT --output toolkit/bounded_dictionary_changes8_measurements.json --cache .tmp/bounded_dictionary --limits 32 --entries 64 256 --max-changed-pixels 8
python toolkit/probe_zx0_storage.py --raw .tmp/bounded_dictionary/bitmap256_rmse0_group512.raw --block-bytes 6144 --quick --zx0 ZX0 --cache .tmp/bounded_zx0_0 --output toolkit/bounded_dictionary_zx0_0_measurements.json
python toolkit/probe_zx0_storage.py --raw .tmp/bounded_dictionary/bitmap256_rmse24_group512.raw --block-bytes 6144 --quick --zx0 ZX0 --cache .tmp/bounded_zx0_24 --output toolkit/bounded_dictionary_zx0_24_measurements.json
python toolkit/review_bounded_dictionary.py --reference CHECKPOINT --candidate .tmp/bounded_dictionary/bitmap256_rmse24_group512.npz --output toolkit/bounded_dictionary_quality_review.json --contact-sheet .tmp/bounded_dictionary/comparison.png
python -m unittest discover -s toolkit -p test_bounded_dictionary.py -v
```
