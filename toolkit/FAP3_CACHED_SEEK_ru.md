# FAP3: смена дорожки без полного TR-DOS

21 сентября 2026. База `9db8954`, опция быстрого чтения одной дорожки.
Вход прежний: 4221 кадр без финальных титров, 25 326 записей AY,
границы частей 1269/2334/3195/4221. Сжатые данные и пиксели не менялись.

## Реализация и память

`--fast-disk --cached-seek` выбирает сторону через 1FEBh/1FF6h и цилиндр
через 3E44h проверенной TR-DOS 5.03. Для следующего чтения устанавливается
флаг задержки установки головки 84h, на той же дорожке — 80h. Сохраняются
настроенная скорость шага привода, регистры ZX0 и независимый дисковый стек.
Короткое чтение по-прежнему повторяется полным C=5.

Адаптер 215 → **227 байтов**, 6000h–60E2h. Новая процедура **89 байтов**,
9A90h–9AE8h, после загрузчика следующей части и до таблицы 9B00h. Сборщик
проверяет границы и неизменность защищённых таблиц. Экраны, 64-КиБ кольцо,
история ZX0, AY и стеки не перемещаются. Вызов процедуры и PUSH HL
занимают четыре байта; вместе с двумя адресами входа в ROM максимальная
RAM-обвязка использует 20 байтов дискового стека вместо 18, то есть +2.
Внутренние стеки ROM и IRQ в этот статический подсчёт не входят.

Испытаны два режима:

- `--cold-track`: первая runtime-операция снова использует C=5;
- обычный `--cached-seek`: запоминает дорожку последнего начального чтения.
  Загрузчик уже инициализировал привод и заполнил кольцо. Новое состояние
  позволяет не повторять C=5 после начала видео; оно вычисляется при сборке.

Без `--cached-seek` прежний машинный путь не меняется. Быстрые профили
остаются опциями и требуют SHA ROM, указанного в метаданных.

## Полные измерения Fuse

Выполнено 12 полных прогонов: четыре части прежнего прямого читателя
с расширенным учётом AY, четыре cached-seek с холодным стартом и четыре
с использованием состояния загрузчика. Все 4221 кадр каждого комплекта
доходят до EOF; AY и 6516 runtime-секторов каждого комплекта точны.
На кадре сверены 80 байтов, а не весь экран; прогресс 100%.

| Часть | Скорость базы → cached seek, кадр/с | Максимальное фактическое отставание, с | Пропущенные поля между AY-записями до → после |
|---|---:|---:|---:|
| 1 | 6,360 → **7,299** | 47,46 → **22,00** | 2380 → **1098** |
| 2 | 5,914 → **6,936** | 52,56 → **26,06** | 2624 → **1299** |
| 3 | 5,084 → **6,027** | 66,54 → **40,06** | 3322 → **1998** |
| 4 | 5,574 → **6,501** | 61,38 → **35,16** | 3064 → **1753** |

Итоговый вариант делает **ноль полных C=5 во время показа**. Прямые чтения
занимают 34,14–34,42 с на часть, смена стороны/цилиндра — ещё около 0,319 с.
У базы оба типа чтения вместе занимали 61,21–61,68 с. Эти окна включают
ROM, эмулируемую задержку диска, IRQ и ULA; они не являются чистыми
CPU-тактами. Суммарно освобождено около 27 с на часть.

Холодный cached seek почти совпадает с итоговым по средней скорости;
передача состояния загрузчика убрала один лишний C=5. Небольшие различия
в отдельных кадрах и счётчиках зависят также от начальной фазы Fuse/диска.
Результаты холодного варианта сохранены отдельно, а не заменены итоговыми.

**Номинальные сроки и резервный допуск не выдержаны.** В итоговом варианте:

- поздних по счётчику: 1222/1059/851/916;
- максимальная задержка по счётчику: 1086/1291/1993/1748 полей;
- фактических OUT за одним полем: 1220/1059/851/969;
- интервалов вне 5..7 полей: 456/546/488/462;
- восстановленных серий: 0/0/0/3, по одной невосстановленной серии в конце
  каждой части. Все отдельные сроки, OUT и серии есть в отчётах.

AY-записи по-прежнему точны по содержимому, но не по времени: счётчики
пустой очереди 1083/1286/1988/1743. Новый показатель вычисляется из реальных
времён завершения AY-записей: для соседних записей суммируется
`max(0, floor(t_next/70908) - floor(t_prev/70908) - 1)`.
Так учитываются и пустая очередь, и пропущенные IRQ. Он относится к полям
между первой и последней записью; это не оценка акустической точности.
Двойных записей в одном поле нет. Исходные времена сохранены полностью.

## T-states игрока

Подсчёт каждой инструкции по Z80; включает вызовы/переходы в ROM и
atomic paging, исключает тела ROM, физический диск, IRQ и ULA.
Внешний CALL адаптера добавляет ещё 17 T в обоих случаях.

| Путь | База, T | Новый, T | Изменение, T |
|---|---:|---:|---:|
| Та же дорожка | 896 | 896 | 0 |
| Холодный C=5 | 804 | 841 | +37 |
| Смена на нечётную логическую дорожку | 804 | 1351 | +547 |
| Смена на чётную логическую дорожку | 804 | 1341 | +537 |
| Последний сектор дорожки | 907 | 907 | 0 |
| Переполнение банка кольца, регион 3 | 944 | 944 | 0 |
| Короткое чтение той же дорожки и повтор | 1023 | 1023 | 0 |
| Смена дорожки, короткое чтение и C=5 | 804 | 1478 | +674 |

В последней строке база делает сразу успешный C=5, новая версия проходит
дополнительную неудачную прямую попытку. Инициализация кеша из загрузчика
меняет только байт состояния, новых исполняемых инструкций не добавляет.

2560 комбинаций 160 дорожек × 4 приводов/скоростей × 4 банков проходят;
проверены обе стороны, край кольца, сохранность регистров и повреждённое
короткое чтение. Первая версия теста неверно требовала нулевые A/B при
выборе стороны (эти регистры не являются её аргументами); исправлен тест,
после чего весь набор выполнен полностью. Четыре прежних теста проходят.
Три продолжения сверены с отдельной загрузкой при mocked ROM; Fuse
подтверждает EOF и ожидание прежнего диска в частях 1–3. Физический привод
и настоящая замена носителя в Fuse не проверялись.

## Повторение и решение

Сборка из `FAP3_FAST_DISK_ru.md`, добавить `--cached-seek`; для контрольной
добавить также `--cold-track`. Выводить в `.tmp/fap3_cached_warm` и
`.tmp/fap3_cached_seek` соответственно. Все прочие параметры, входы
и хеши остаются прежними. Затем:

```text
python toolkit/benchmark_fap3_cached_seek.py --output .tmp/fap3_cached_seek/cpu.json
python -m unittest discover -s toolkit -p test_fap3_disk.py -v
```

Для обеих сборок прогнать `measure_fap3_fuse.py` на всех частях; им же
повторить базовые образы с выводом в `.tmp/fap3_same_track_ay`.
`test_fap3_disk.py --volumes` и `verify_fap3_prompt_fuse.py` запускать
для итоговой сборки, как в предыдущей инструкции. Архивирование:

```text
python toolkit/summarize_fap3_cached_seek.py --baseline .tmp/fap3_same_track_ay --cold .tmp/fap3_cached_seek --warm .tmp/fap3_cached_warm --output toolkit/fap3_cached_seek
```

[Сводка и покадровые отчёты](fap3_cached_seek/summary.json),
[CPU](fap3_cached_seek/cpu.json), [измеритель](measure_fap3_fuse.py).

Сохранить cached seek как основу следующих дисковых опытов: значимый
выигрыш без роста потока и количества занятых секторов. Корневые образы
пока не заменять: частота, AY и три дискеты ещё не достигнуты. Следующий
опыт — порядок секторов 1,9,2,10,… и затем перенос чтений из критического
участка декодера в свободные интервалы с контролируемым резервом.
