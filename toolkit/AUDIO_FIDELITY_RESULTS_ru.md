# Улучшенная мелодия и адаптивный шум AY

17 сентября 2026, база `9fa1d17`. Все 1000 кадров исходного видео сохранены.
Музыка анализируется совместно по гармоникам; есть настоящие паузы,
раздельная громкость партий и ограничение скачков мелодии. На 217 кадрах
(26,04 с из 120 с) канал B воспроизводит шум вместо слабого сопровождения.
Бас A и мелодия C при этом сохраняются.

## Аудиосравнение

Все версии синтезированы одним методом: непрерывные фазы, ограниченные
по частоте прямоугольные тоны, номинальные ступени громкости 3 дБ.
Шум — непрерывный 17-битный LFSR с четырёхкратной дискретизацией и усреднением.
Это приближённое превью, не запись реального AY или аудиовыхода Fuse.

| Показатель | Прежний анализ | Новый, тоны | Новый, тоны и шум |
|---|---:|---:|---:|
| Спектральный косинус по полутонам | 66,28% | 81,63% | 83,08% |
| Косинус chroma, без различия октав | 85,76% | 94,42% | 94,78% |
| Корреляция динамики RMS | 93,15% | 98,51% | 98,86% |
| F1 атак, допуск ±120 мс | 67,39% | — | 69,85% |

Сравнение с оригинальным фронтальным миксом: 120 с, 1000 кадров;
спектр и динамика оцениваются на 870 кадрах громче −55 dBFS.
Детектор атак по всему фрагменту обнаружил 134 события оригинала,
138 новых и 95 совпадений. F1 = 2×95/(134+138).
Изменений мелодии 300; скачков больше семи полутонов 12 вместо прежних 14.
Это не доказывает правильность каждой распознанной ноты.

**95% не достигнуты.** [Критерии и дальнейший план](AUDIO_FIDELITY_PLAN_ru.md)
сохранены отдельно. Проценты в таблице — шкала технических показателей,
не оценка сходства на слух. WAV оригинала/до/после охватывают 60–84 с;
все три имеют RMS 0,1 для сравнения без преимущества громкости.

## Шум и формат

У AY один общий шумовой генератор. Канал B переключается между тоном
и шумом; A/C остаются тональными. Шум включается, когда широкополосная
часть заметна и громче слабой партии B. Узкие гармонические пики подавляет
медиана по 17 частотным отсчётам. Выбирается период 1–31 по сходству
формы спектра с моделью удерживаемого случайного сигнала.

Размер состояния остаётся 9 байт:

| Поле | Значение |
|---|---|
| Байты 0/1, 2/3, 4/5 | Три 12-битных периода тона |
| Байт 1, биты 7–4 | Младшие 4 бита периода шума |
| Байт 3, бит 4 | Старший бит периода шума |
| Байты 6–8 | Громкости A/B/C, 0–15 |
| Период шума 0 | R6=0, R7=38h: только три тона |
| Период шума 1–31 | R6=период, R7=2Ah: шум B, тоны A/C |

Перед выводом старшие биты периодов A/B маскируются. R6/R7 обновляются
каждый кадр, включая возврат от шума к тону. Промежуточный ZXVL с шумом
имеет версию 5 и предназначен для перепаковки; прежний проигрыватель v4
его отклоняет. Дисковый ZXFC получает версию 10; проигрыватели v9/v10 отклоняют
несоответствующий поток. Старые тональные сборки по-прежнему используют v9.
Шум включается явным `retune_ay_build.py --noise`, затем fast builder
автоматически выбирает v10. Другие режимы упаковки с шумом отклоняются.

Описание регистров и частот:
[Yamaha YM2149](https://www.ym2149.com/ym2149.pdf).
Обратная связь LFSR bit0 XOR bit3 сверена с
[реализацией MAME и её проверкой на чипах](https://raw.githubusercontent.com/mamedev/mame/master/src/devices/sound/ay8910.h).

## Цена вывода AY

Счёт по [Zilog UM0080](https://www.zilog.com/docs/z80/um0080.pdf),
от входа `ay_apply` до RET; CALL, IRQ, ULA, ROM и дисковая задержка исключены.

| Путь | До, T | После, T | Разность, T |
|---|---:|---:|---:|
| Старый проигрыватель, три тона | 624 | 624 | 0 |
| v10, кадр с тремя тонами | 624 | 790 | +166 |
| v10, кадр с шумом B | 624 | 792 | +168 |

Старый путь: выбор/запись R7 55 + LD HL 10 + 9×61 + RET 10 = 624 T.
Новый: распаковка/выбор микшера 103/105 + две записи по 52 + LD HL 10 +
9×61 + две AND по 7 + RET 10 = 790/792 T. Одна запись прежнего регистра:
LD A,n 7 + LD BC,nn 10 + OUT 12 + LD A,(HL) 7 + INC HL 6 + LD B,n 7 + OUT 12.
Дополнительная цена около 0,047 мс на кадр при 3 546 900 Гц.
Тест выполняет машинный код для всех 31 периода и отключения шума.

## Диск и полный прогон

Fuse 1.9.0, Spectrum 128 + Beta128, TR-DOS 5.03:

- 1000 кадров, 999 интервалов: среднее 119,932 мс, максимум 124,766 мс,
  8,338 кадра/с. Ни одного интервала длиннее 125 мс.
- PLAYER 5120 байт (20 секторов). Одна TRD 655360 байт, свободен один сектор.
- Полезный поток 2521 сектор: на четыре больше старой музыки, на один
  больше нового анализа без шума. Длина аудиокадра не изменилась;
  изменился результат сжатия. Физический VIDEO с заголовком — 2522 сектора.
- Среднее обслуживание ROM 7,925 мс; максимум 193,409 мс включает запуск.
  Это время Fuse с IRQ и моделью диска, не измерение физического привода.

CPU-валидатор сверил все 1000 экранов, предыдущие экранные банки и регистры
AY, включая шум/микшер. 2522 чтения с заголовком, недогрузок и fatal нет.
Пройдены 73 прежних теста проигрывателя и 15 аудиотестов, включая IRQ
на каждой границе инструкции шумового `ay_apply` и возврат к тональному B.

Подготовка CPU: основная в среднем 124447,413 T, фоновая 89572,734 T,
в сумме 214020,147 T. У старой музыки сумма 214269,798 T. Изменились
сжатые блоки и распределение работы; это не цена самой процедуры AY.
Для полного времени, включая её вывод, paging и диск, используется Fuse.

## Повторение

Команды из `toolkit`. MOV — исходный фильм, SOURCE — прежняя сборка
`build_long_center_crop_feedback_melody_no_gray_25over3fps`.
Нужны NumPy, зависимости существующего toolkit, FFmpeg в PATH и ZX0.

```text
python retune_ay_build.py --input-video MOV --source-build SOURCE --output build_audio_noise --noise
python build_fast_sparse_trd.py --source-build build_audio_noise --output build_audio_noise_trd --packing zx0 --zx0 /path/to/zx0 --drawing registers --disk-reader trdos503-irq --disk-layout interleaved --pacing deadline --zx0-decoding incremental --motor-keepalive-fields 64 --prefetch-quota 3 --rom-clock full --disk-seek cached --packet-lookahead --uncontended --read-reserve 64 --memory-clock --direct-input --wrapped-input
python compare_ay_fidelity.py --input-video MOV --baseline-build SOURCE --build build_audio_noise --output build_audio_noise_comparison --ffmpeg /path/to/ffmpeg
python -m unittest test_ay_fidelity test_ay_noise test_wrapped_input test_direct_ring_input test_memory_clock test_read_debt test_uncontended_player test_packet_lookahead test_fast_drawing test_fast_seek test_playback_schedule test_disk_layout test_blocked_stream test_packed_stream test_incremental_zx0
python measure_fuse.py /path/to/fuse.exe build_audio_noise_trd --output build_audio_noise_trd/fuse_timing.json
python validate_fast_sparse.py build_audio_noise_trd --source-build build_audio_noise --fuse-timing build_audio_noise_trd/fuse_timing.json --output build_audio_noise_trd/cpu_validation.json
```
