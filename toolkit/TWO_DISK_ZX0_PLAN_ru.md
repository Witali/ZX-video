# Две дискеты ZX0 при прежнем разрешении

Запрос: полный мультфильм на двух стандартных TRD. Прежнее разрешение
128×96 логических точек, развёртка 256×192 и сетка атрибутов 32×24 сохраняются.
Полная длительность — 596,52 с; 4971 кадр, 25/3 кадра/с; AY — все 29826
состояний при 50 Гц, включая шум. Звук берётся из проверенного выпуска.

## Бюджет

Две TRD по 655360 байт; после служебной дорожки, boot и прежнего PLAYER
остаётся 1 291 776 байт. Из этого бюджета также оплачиваются заголовки,
выравнивание и возможный рост проигрывателя. Предыдущий лучший замер
обратимой упаковки: 2 894 676 байт видео ZX0 + 77 696 байт неизменённого AY.

## Порядок работы

1. Сохранять качество, разрешение, полный фильм и 25/3 кадра/с.
   Новое требование плавности не разрешает потери изображения или звука.
2. Освободить время CPU для ZX0, проверяя каждый интервал переключения
   экрана. Продолжать поиск обратимого представления данных. Варианты
   с потерями требуют отдельного разрешения; сейчас они не используются.
3. Измерить реальные пакеты ZX0, включая звук и независимый начальный
   кадр каждой дискеты. Простая оценка DEFLATE не считается доказательством
   попадания в бюджет. Использовать существующий проверенный проигрыватель,
   если новый профиль совместим с ним.
4. Собрать ровно две TRD. Проверить все экраны относительно выбранного
   профиля, все AY-такты относительно прежней дорожки, прогнать обе дискеты
   в Fuse. Сравнение с прежним изображением хранить отдельно от проверки
   точности декодирования нового профиля.
5. После успешных проверок сохранить новый комплект в корне через Git LFS,
   удалить прежние корневые варианты, обновить описание и отправить коммиты.

## Приёмка

Две стандартные TRD; полный мультфильм и прежнее разрешение; переключения
в Fuse строго через шесть полей, отклонение интервала от шести полей ≤1 мс,
AY до 25 мс; без пропущенных тактов и недогрузок. Сходство
изображения не выдавать за побайтное равенство, если разрешён профиль с потерями.
Для изменений горячего пути Z80 записать абсолютные T-states и разницу;
ROM, IRQ, ULA и дисковые задержки учитывать отдельно. Экспериментальная
перекодировка на ПК сама по себе не изменяет инструкции PLAYER: 0 T.

## Проверки без потерь

`canonicalize_display_cells.py` проверяет другой способ записи одинаково
выглядящих ячеек. Одноцветная ячейка хранится через PAPER; в двуцветной
ячейке без промежуточных уровней можно поменять INK/PAPER и инвертировать
bitmap. Изменены 1 645 088 представлений ячеек, но все отображаемые RGB
пиксели всех 4971 кадров совпали с исходными. Прочитанный обратно поток
также совпал с новым представлением и прежними AY-байтами. Отдельный тест
сверяет расчёт цветов с существующим native-screen renderer для всех
128 атрибутов без FLASH и разных рисунков.

Отчёт: `display_canonicalization_measurements.json`. Это экспериментальный
вариант без потери видимого качества; он не включён в текущий выпуск.
Изменение инструкций проигрывателя — 0 T; скорость нового набора пакетов
в Fuse не заявляется.

ZX0-опыт остановлен после выхода за бюджет. `assess_cached_zx0_budget.py`
заново воспроизвёл разбиение полного видео со всеми 29826 AY-тактами,
проверил соответствие кэша и распаковал каждый готовый блок. Для выбранного
разбиения 379 из 747 блоков уже требуют **2 121 066 байт** с заголовками
против 1 291 776 доступных. Остальные блоки в этой оценке считаются нулевыми.
Поэтому этот конкретный вариант отклонён без досжатия оставшейся части.
`equivalent_cells_budget.json` явно помечен `complete: false`; указанное
число — нижняя оценка этого фиксированного разбиения, а не размер полного
фильма и не предел других способов кодирования или границ томов.

```text
python toolkit/canonicalize_display_cells.py --source-build ORIGINAL_SOURCE --output toolkit/build_equivalent/source
python -m unittest discover -s toolkit -p test_display_canonicalization.py
python toolkit/benchmark_ay_encoding.py --source-build toolkit/build_equivalent/source --ay-50hz AUDIO --player-build ORIGINAL_DISKS --zx0 ZX0 --output toolkit/build_equivalent/encoding --formats pairs
python toolkit/assess_cached_zx0_budget.py --source-build toolkit/build_equivalent/source --ay-50hz AUDIO --cache toolkit/build_equivalent/encoding/cache --output toolkit/equivalent_cells_budget.json
```

Новая сборка на двух TRD пока не создана. Требование сохранять качество
действует; потери не разрешены.

## Уточнение: плавные 8⅓ кадра/с

Оптимизация вывода атрибутов и полная проверка описаны в
`SMOOTH_CADENCE_RESULTS_ru.md`. Новый комплект на 19 TRD сохраняет все
изображения/AY и показывает каждый кадр через шесть прерываний, с
максимальным отклонением интервала 0,240 мс. Это проверенный промежуточный
выпуск, заменяющий 30 TRD. Цель двух дискет остаётся незавершённой.
