# Поддержание мотора без повторного чтения сектора

15 сентября 2026. База — `8674c91`. Максимальный интервал показа сократился
с 363,308 до **224,762 мс**. Средняя скорость 8,250 кадра/с; цель плавных
8 кадров/с ещё не выполнена: 238 интервалов длиннее 125 мс.

## Причина и исправление

В предыдущей сборке при заполненном кольце плеер раз в 64 поля читал
следующий сектор в 7C00h, сохранял курсор потока, затем позднее перечитывал
этот сектор в кольцо. Трасса адресов назначения показала: все шесть
вызовов около 193 мс следуют непосредственно за такими чтениями в 7C00h.

Для `--disk-seek cached` поддержание мотора теперь использует штатную
процедуру ROM 3E44h: SEEK с HLD на **текущий физический цилиндр**. Используется
кеш последней прочитанной дорожки, поскольку следующий сектор потока может
принадлежать другой дорожке. Головка не перемещается, сторона не меняется,
сектор не читается. Кольцо, курсор потока и флаг установки головки следующего
READ сохраняются. По окончании обновляются часы последнего обслуживания.
В режиме `dispatcher` прежний способ со scratch-чтением сохранён.

По [документации WD179x в руководстве NABU](https://device.report/m/47e313e43c018d5387d7a59d6f0d70c69088cc3c4dc8432a273d65294b214c91)
Type-I команда с h=1 управляет HLD, а простой отсчитывается индексными
импульсами. Использован тот же проверенный ROM 5.03 и полный обработчик
часов, что в [cached seek](CACHED_SEEK_RESULTS_ru.md). Адреса других ROM
этим экспериментальным профилем не поддерживаются.

## Полный прогон Fuse

Spectrum 128 + Beta128, Fuse 1.9.0, 3 546 900 Гц; эмулируемое время.

| Показатель | Scratch-чтение | SEEK текущего цилиндра |
|---|---:|---:|
| Средняя скорость, кадр/с | 8,246 | 8,250 |
| Средний интервал, мс | 121,271 | 121,206 |
| Максимальный интервал, мс | 363,308 | 224,762 |
| Интервалов длиннее 125 мс | 238 | 238 |
| Секторных чтений с заголовком | 2524 | 2518 |
| Чтений в 7C00h | 6 | 0 |
| Прямых чтений дольше 100 мс во время показа | 6 | 0 |
| Старт PLAYER → первый кадр, мс | 3556,666 | 3557,739 |

Во время показа 2197 прямых чтений занимают 18,947 с, максимум 43,879 мс;
282 вызова смены стороны/SEEK — 0,426 с. Последние включают восемь
поддержаний мотора и не являются секторными чтениями. Совокупно ROM и
диск занимают 19,374 с. Первый C=5 перед стартом остаётся около 193 мс.
Ожидания смены дорожки и аппаратной установки головки сохраняются.

Данные не менялись: 1000 кадров и AY, 112 блоков, 2517 секторов полезного
потока, PLAYER 4096 байт, пять свободных секторов, одна TRD.
CPU подготовки остаётся 211 101,761 T в среднем и 605 829 T максимум.
Подкачка выполняется после границы этого CPU-замера; её стоимость ниже.

## Детерминированные такты

[Zilog UM0080](https://www.zilog.com/docs/z80/um0080.pdf), вход `producer_one`
→ RET при полном кольце. Включены RAM CALL/JP; тела/возвраты ROM, диск,
IRQ и contention исключены и измерены отдельно выше.

| Путь | До, T | После, T | Разность, T |
|---|---:|---:|---:|
| Поддержание ещё не требуется | 214 | 214 | 0 |
| Требуется поддержание | 929 | 476 | −453 |
| Конец потока | 125 | 125 | 0 |

Новая процедура `keepalive_seek` занимает 258 T; общий путь 476 T включает
проверку заполнения, оставшихся секторов и времени, переход к процедуре и
возврат producer. Переключение быстрого/полного ISR — по 46 T. Сам короткий
ISR неизменен: 61 → 61 T, разность 0; обычная ветвь полного ISR — 160 T.
[Машинные суммы и допущения](motor_keepalive_cycles.json).

## Проверки и продолжение

31 тест прошёл. Новый тест проверяет все 160 логических дорожек, случай
перехода следующего сектора на другую дорожку, границу 64 полей, переполнение
часов и конец потока. Проверены цилиндр, отсутствие чтений/записей в кольцо,
курсор, счётчики, стек, HL′, восстановление ISR и флаг READ.
Полный CPU-прогон сверяет все экраны и AY; Fuse проверяет завершение 1000
кадров без fatal и недогрузки. Это измерения эмулятора; физический дисковод
и поведение при аппаратных ошибках отдельно не проверены.

Следующий приоритет — перенос сжатого блока и распаковка заранее. Например,
кадр 532 требует 605 829 T CPU, из них 154 449 T — копирование блока.
Три обычных секторных чтения после его подготовки добавляют около 19 мс.
Для равномерного показа эту работу нужно распределить во времени.

## Воспроизведение

Опции сборки прежние; `--disk-seek cached` автоматически выбирает новый
способ при ненулевом `--motor-keepalive-fields`. Метаданные записывают
`motor_keepalive_method: seek-current-cylinder`.

```text
python build_fast_sparse_trd.py --source-build SOURCE --output build_seek_keepalive_v9 --packing zx0 --zx0 /path/to/zx0 --drawing registers --disk-reader trdos503-irq --disk-layout interleaved --pacing deadline --zx0-decoding incremental --motor-keepalive-fields 64 --prefetch-quota 3 --rom-clock full --disk-seek cached
python benchmark_motor_keepalive.py --baseline-build build_stream_rle_v9 --build build_seek_keepalive_v9 --output build_seek_keepalive_v9/cycles.json
python measure_fuse.py /path/to/fuse.exe build_seek_keepalive_v9 --output build_seek_keepalive_v9/fuse_timing.json
python validate_fast_sparse.py build_seek_keepalive_v9 --source-build SOURCE --fuse-timing build_seek_keepalive_v9/fuse_timing.json --output build_seek_keepalive_v9/cpu_validation.json
```
