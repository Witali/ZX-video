# Парный вывод RLE: все интервалы короче 125 мс

17 сентября 2026. База — `ba6cab7`. В полном ролике из 1000 кадров
получены **8,337 кадра/с**, средний интервал **119,947 мс**, максимальный
**124,259 мс**. Все 999 интервалов укладываются в бюджет 8 кадров/с.
Это подтверждает цель для текущего ролика в Fuse 1.9.0, Spectrum 128 +
Beta128 с проверенной TR-DOS 5.03. Физический дисковод отдельно не измерен.

## Изменение

Два соседних значения RLE выводятся за одну итерацию. Первое записывается
в верхнюю, затем нижнюю строку; второе — в нижнюю, затем верхнюю. Указатель
возвращается к верхней строке. Это убирает лишние переключения адреса
и одну проверку счётчика. Нечётная длина обрабатывается отдельным первым
значением; для единичной литеральной серии есть короткий путь.

Повторяемый цвет раскрывается один раз в D/E, экран адресуется через HL.
Соседние команды RLE передают указатель потока непосредственно через HL,
минуя общий диспетчер. Перед другой командой IX восстанавливается.
Формат потока, все уровни яркости, порядок кадров и AY сохранены.

свободны три сектора. Чтений с заголовком — 2518, дополнительных нет.

CPU-валидатор сравнил каждый из 1000 экранов, предыдущий экранный банк,
видимый банк и AY с исходником, воспроизведя часы полного прогона Fuse.
Недогрузок и fatal нет. До конца дисковых данных выполнена 901 проверка
резерва: минимум 83 сектора при настройке 64. Стек не ниже 9D64h.
Расхождение часов с полями Fuse −0,173 поля укладывается в фазу поля.

73 теста прошли: полный набор из 72 и дополнительный тест IRQ для нового
RLE. Проверены все 96 строк, оба экрана, 256 значений цвета, литералы длиной
1–32, повторы 2–32, цепочки до 96 строк и возврат к другим командам.
IRQ-тест прерывает смешанную цепочку всех длин примерно каждые 233 T
и сравнивает экраны с прежним декодером. Это проверка сохранности регистров,
а не модель фаз ULA. Изображение внутри Fuse отдельно не сравнивается;
пиксели проверяет CPU-валидатор, Fuse проверяет полное время и завершение.

## Детерминированные такты Z80

Основа — [таблица Zilog UM0080](https://www.zilog.com/docs/z80/um0080.pdf).
IRQ, ULA contention, ROM и физическая задержка диска исключены.
[Машинные суммы](rle_pair_cycles.json) сравнивают сохранённые бинарники.

| Путь | До, T | После, T | Разность, T |
|---|---:|---:|---:|
| Строка из 32 литералов | 3119 | 2447 | −672 |
| Строка из 32 одинаковых значений | 1840 | 1298 | −542 |
| Пакет четырёх литеральных строк с END | 13012 | 9808 | −3204 |
| Пакет четырёх повторяющихся строк с END | 7896 | 5212 | −2684 |
| Переход между соседними строками RLE | 183 | 37 | −146 |
| Выход к другой команде | 35 | 61 | +26 |

Строка измеряется от входа команды до `command_loop`, без диспетчера.
Пакет включает все диспетчеры и завершающий END/RET.

Литеральная пара: два тела по 53 T и управление 29 T = 135 T
вместо двух итераций по 90 T = 180 T. Последняя пара на 9 T короче.
Каждое тело: `LD C,(HL)` 7, `INC HL` 6, два `LD A,(BC)` по 7,
два `LD (DE),A` по 7, три INC/DEC по 4. Проверка/переход использует
EX AF/DEC по 4, JR 7/12, JP 10. RRA — 4 T; carry предварительно очищен OR.

Пара повторов: четыре `LD (HL),r` по 7, четыре INC/DEC по 4,
DJNZ 13/8 = 57/52 T. Прежде две итерации стоили 94/89 T.
Два дополнительных `EX DE,HL` стоят суммарно 8 T на серию.
Carry для деления счётчика RRA сохранён после ADD 2: исходная длина
не переполняет байт. Длины повторов не меньше двух, поэтому B не нулевой.

Точный счёт отдельной строки, L/R — число литеральных/повторных серий,
NL/NR — их суммарные длины, NL+NR=32:

```text
До:    189 + 50L + 147R + 90NL + 47NR
После: 215 + 50L + 155R + 90NL + 39NR + sum(DL(n)) + sum(DR(n))
Разность: 26 + 8R - 8NR + sum(DL(n)) + sum(DR(n))

DL(1) = -2
DL(n чётное) = 22 - 45*floor(n/2)
DL(n нечётное > 1) = 4 - 45*floor(n/2)
DR(n чётное) = 16 - 21*floor(n/2)
DR(n нечётное) = -2 - 21*floor(n/2)
```

DL суммируется по литералам, DR — по повторам. Для цепочки из суммы
новых отдельных строк с диспетчерами вычитается 172 T за каждый стык.
Старый стык: выход 35 + диспетчер 123 + IX→HL 25 = 183 T.
Новый: LD 7 + CP 7 + JR 7 + INC HL 6 + JP 10 = 37 T.
Неуспешная проверка следующей команды добавляет 7+7+12 = 26 T.
Быстрый ISR по-прежнему 116 T, перенос PLAYER при старте прежний.

```text
python measure_fuse.py /path/to/fuse.exe build_rle_pair_runs --output build_rle_pair_runs/fuse_timing.json
python validate_fast_sparse.py build_rle_pair_runs --source-build SOURCE --fuse-timing build_rle_pair_runs/fuse_timing.json --output build_rle_pair_runs/cpu_validation.json
```

[Хеши, условия и полные итоговые показатели](rle_pair_measurements.json).

с парными литералами — 126,676 мс; с парными повторами — 124,259 мс.

## Проверка цели

- Темп: 1000 кадров, 999 реальных интервалов Fuse; каждый ≤125 мс.
- Сохранность: все экраны и AY совпали, кадры не пропускаются.
- Диск: одна TRD, VIDEO прежний, дополнительные сектора не понадобились.
- Надёжность в проверенном окружении: нет недогрузок/fatal, резерв ≥64,
  пройдены границы банков/секторов, переполнение часов и IRQ-тесты.
- Воспроизводимость: сохранены формулы, сравнение бинарников, хеши,
  параметры сборки и проверки. Реальный привод требует отдельного замера.
