# Кэш текущего байта Хаффмана в B

25 сентября 2026. База `ab76fa1`, три самостоятельных диска
`register-fragments`, 4221 кадр без титров. Разрешение, 25/3 fps,
все компактные пиксели, AY и сжатые ZX0-блоки сохранены.
**Полный замер выполнен; требования по срокам видео и AY не пройдены.**

## Изменение и такты

В `carry_huffman` повторное `LD L,(IX+0)` заменено на `LD L,B`:
19 → 4 T. B хранит текущий байт; он инициализируется при начале кадра
и обновляется при переходе на следующий байт и возврате длинной ветви.
Чтение `(IX+1)` осталось. Внутри реконструктора это B' после `EXX`;
вызывающие участки и AY IRQ сохраняют его. Литеральный канал отдельный,
через HL; конфликтующие режимы отклоняются генератором.

Цены по [таблице Zilog UM0080](https://www.zilog.com/docs/z80/um0080.pdf),
без ULA, IRQ и диска:

| Путь | Раньше | С кэшем | Разница |
|---|---:|---:|---:|
| Короткий bitmap-код внутри байта | 160 T | 145 T | −15 T |
| Короткий bitmap-код с переходом байта | 165 T | 169 T | +4 T |
| Соответствующий attribute-код | на 1 T меньше | на 1 T меньше | та же |
| Длинный код | `Tlong` | `Tlong+4` | +4 T |
| Инициализация B на кадр | 0 T | 19 T | +19 T |

Абсолютная формула длинного пути прежнего carry-декодера:
`Tlong = 420 + 53*(L−9) + 32*R − K + 78*[s>0] + 5*[e>0] − A`,
где L — длина кода, s/e — начальное/конечное смещение бита,
`R=ceil(max(0,L−8−(8−s if s>0 else 0))/8)`, A=1 для attribute,
K=1 при переносе при сложении младшего адреса таблицы символов и индекса.
Формула и каждое исполненное время проверяются в
[benchmark_prefix_huffman.py](benchmark_prefix_huffman.py).

На кадр: `ΔT = 19 − 15*Nshort + 19*Ncross + 4*Nlong`.
Ncross входит в Nshort. На реальных таблицах выполнены 22904 парных
случая на каждый диск: все символы и все восемь смещений.

Примитив вырос **235 → 239 байт**, реконструктор вместе с инициализацией
**4017 → 4024**; конец `8FB8`, до `9000` остаётся 72 байта.
Таблицы, переменные и стек не выросли. Последний доступ использует только
прежний guard-байт; пустой поток тоже допустим.

## Полный CPU-прогон

Исполнены все 4221 кадр: компактное состояние и оба полных экрана точны,
проверяются чтения/записи и сохранность TR-DOS workspace. База на каждый
кадр — полный сохранённый CPU-прогон плюс измеренная дельта compiled masks;
первые восемь кадров каждого диска повторно исполнены и старым кодом.
Числа коротких/длинных ветвей сверены с прежней статистикой каждого кадра.

| Диск | Раньше, T | С кэшем, T | Разница, T |
|---|---:|---:|---:|
| 1 | 394673177 | 393427445 | −1245732 |
| 2 | 334699952 | 333543566 | −1156386 |
| 3 | 314259962 | 313219910 | −1040052 |
| Всего | 1043633091 | 1040190921 | **−3442170 (−0,330%)** |

51 кадр стал дороже; диапазон дельты −2510…+19 T. Здесь нет стоимости ZX0,
диска, ULA и реального расписания IRQ. Это ускорение проверенного пути
кадра, а не всего времени воспроизведения.

## TRD и Fuse

Кэш встроен в настоящий bootstrap. Использовано прежнее число секторов:
**2543/2544/2543**; начало видео **55/59/62**, читается **2504/2501/2496**.
Сжатые потоки побайтно прежние: **641005/640198/638742 байта**.
Каждый диск загружен независимо. CPU с подменёнными ROM-сервисами сверил
восстановление пяти секций RAM; секция A000 со staging не сравнивалась
с её исходным образом после загрузки. Обе смены диска, сообщение,
отказ от неверного диска/серии и итоговая RAM следующего тома проверены.

В Fuse поверх этого устанавливаются прежние очередь слотов и compiled masks.
Они ещё остаются отладочной надстройкой; вместимость общего окончательного
загрузчика этим опытом не подтверждена. Все три прогона дошли до EOF,
все **25326 AY-записей точны**, все **7501 чтение** сверены, retries=0.
Fuse сверяет 80 экранных байтов на кадр; полный экран проверен CPU отдельно.

| Диск | Late раньше → кэш | AY underruns раньше → кэш | Фактическая средняя fps с кэшем |
|---|---:|---:|---:|
| 1 | 990 → 989 | 327 → 321 | 8,067402 |
| 2 | 1142 → 1125 | 803 → 794 | 7,556851 |
| 3 | 1272 → 1272 | 1011 → 1000 | 7,402553 |
| Всего | **3404 → 3386** | **2141 → 2115** | — |

Сумма интервалов от первой до последней публикации:
1945290074 → 1943446461 T (**−0,095%**). Начальные IRQ/дисковые фазы
не выровнены, поэтому эта разница не является изолированным замером кэша.
Read service 235711205 → 235722720 T; seek service 5185521 → 5192800 T.
В эти интервалы входит исполнение CPU/ROM/IRQ/ULA/контроллера; выделять из
них чистую физическую задержку нельзя. Физический привод не проверялся.

Максимальное опоздание счётчика: **326/799/1005 полей**;
фактического OUT: **23186921/56655498/71262539 T**. Неверных фактических
интервалов **404/473/513**, выходов за одно поле **1142/1116/1272**.
Восстановились **1/5/2** серии опозданий; последняя серия каждого диска
тянется до EOF. В отчётах сохранён каждый кадр и каждая серия.
**Основной срок, резервный допуск и AY 50 Гц не выполнены.**

## Охват и решение

- Тесты: все коды/битовые позиции, смешанные символы и чанки, последний
  guard, пустой поток, motion/intra/fragment/attributes, AY IRQ после
  каждой инструкции примитива и полного кадра. **11 тестов прошли**,
  включая расписание публикации, восстановление дедлайнов и неизменность
  машинного кода режима по умолчанию.
- Универсальный конвертер: шесть новых источников, **68 кадров, 8 TRD,
  408 AY ticks**, включая портрет, разные пропорции, звук длиннее видео,
  цветной ролик со сменой дисков и 48 шумовых кадров. Полный CPU-контроль;
  для этих источников нового Fuse-прогона нет.
- Сохранить опцию `--cached-huffman-byte --carry-huffman`, по умолчанию
  выключенную: частоты кодов другого видео могут дать иной результат.
  Для следующего совмещённого прототипа этот кэш пригоден, но сам по себе
  недостаточен. Следующий этап — убрать literal CALL/RET ZX0.
- Корневые релизные TRD не заменять. Пересобранный опыт находится в
  `.tmp/three` рабочего checkout; воспроизводится скриптом ниже.

Зафиксированы и промежуточные неудачи: попытка установить весь изменённый
реконструктор через debugger потребовала таблицы патчей 6278 байт при
буфере 4096 (ZX0 2854 при лимите 2560). Fuse тогда не запускался.
Встраивание кода в bootstrap вернуло таблицу к 2074 байтам.
Первый generic-прогон остановился на отсутствующем `metadata_extra_writes`:
копирование `__dict__` не переносило значения класса проверочного CPU.
Теперь оба параметра проверки памяти передаются явно; машинный код
этим исправлением не меняется. Полный повтор generic прошёл.

```powershell
python toolkit/build_cached_huffman_byte.py --directory ../register-fragments/.tmp/three --raw-directory ../volume-huffman/.tmp/probe --states ../three-disk-quality/.tmp/no_credits/source/conversion.npz --zx0 ../audio-fidelity/.tmp/bin/zx0.exe --output .tmp/three --report toolkit/cached_huffman_byte_build.json
python toolkit/measure_cached_huffman_byte.py --fuse 'C:/Program Files (x86)/Fuse/fuse.exe' --directory .tmp/three --raw-directory ../volume-huffman/.tmp/probe --states ../three-disk-quality/.tmp/no_credits/source/conversion.npz --zx0 ../audio-fidelity/.tmp/bin/zx0.exe --output .tmp/cached
python toolkit/check_generic_converter.py --output .tmp/generic-fixed --report toolkit/cached_huffman_byte_generic.json --ffmpeg ../audio-fidelity/.tmp/bin/ffmpeg.exe --ffprobe ../audio-fidelity/.tmp/bin/ffprobe.exe --zx0 ../audio-fidelity/.tmp/bin/zx0.exe --noise-frames 48 --inline-matches --startup-delta --fast-noop-scan --static-cache-borders --carry-huffman --register-fragments --irq-safe-paging --cached-huffman-byte
python toolkit/summarize_cached_huffman_byte.py --fresh .tmp/cached
python toolkit/summarize_cached_huffman_byte.py
```
