# Перенос compact/cache в память без задержек ULA

25 сентября 2026, база `30de92c`. Эксперимент с теми же тремя TRD,
FAP3/ZX0, 4221 кадром и AY 50 Гц. **Требования по срокам не пройдены.**

## Размещение

Вместо изменения потока проверен обмен местами входного пакета и часто
используемых рабочих данных. Экраны по-прежнему строятся прямо в скрытом
экранном банке. Размеры, команды декодера и разрешение не меняются.

| Данные | Было | Стало | Байт |
|---|---|---|---:|
| Компактный кадр | 6400..72FF | A800..B6FF | 3840 |
| Кэш движения | 7400..77FF | A400..A7FF | 1024 |
| Развёрнутые маски | A4C0..A69F | B700..B8DF | 480 |
| Входной пакет | A6A0..B8FF | 6400..765F | 4704 |
| Векторы отдельного CPU-стенда | A400..A4BF | 7660..771F | 192 |
| Native map отдельного CPU-стенда | 7300..734F | 7720..776F | 80 |

В настоящем проигрывателе векторы и native map остаются внутри пакета;
две последние строки нужны отдельному тесту стадий. Предел реального
пакета — прежние 4703 байта плюс guard. AY A000..A3FF, IRQ, стек,
TR-DOS workspace, код, Huffman и четыре слота ZX0 сохраняют свои области.
Кэш выровнен на 1024 байта; младшие адресные биты кадра сохранены.
Объём дополнительной runtime-памяти — **0**.

[`uncontended_frame.py`](uncontended_frame.py) меняет только адресные
операнды перечисленных инструкций и 16 старших байтов таблицы строк кэша.
Для полного проигрывателя получается 72 изменённых байта. Это ограниченный
стенд текущей сборки, не универсальный пересборщик произвольного бинарника.

Каждая дискета сначала самостоятельно загружает исходный checkpoint.
Временный установщик переносит его Z80-командами перед стартом драйвера:
3840 и 1024 байта. Стоимость двух `LDIR` с установкой трёх пар регистров:
`(25 + 21×3840) + (25 + 21×1024) = 102194 T`, без ULA. Пересылки происходят
один раз до проигрывания. В будущем bootstrap может распаковывать checkpoint
сразу на новые адреса; здесь такой bootstrap и его дисковая ёмкость не проверены.

## Такты и точность

Число детерминированных тактов горячего пути не изменилось: адресные
операнды имеют прежние длины инструкций и цены. Полный журнал содержит
абсолютные и относительные значения для каждой изменённой инструкции:
`LD rr,nn` — 10 → 10 T; сравнение/OR с константой — 7 → 7 T; дельта 0.
Источник — [таблица Zilog](https://www.zilog.com/docs/z80/um0080.pdf).

[`benchmark_uncontended_frame.py`](benchmark_uncontended_frame.py) исполняет
все стадии на Z80 для каждого из трёх независимых стартов. Проверяются все
3840 байт compact, оба полных экрана, metadata, входные курсоры, paging
и запрет записи вне рабочих областей. Сравнение тактов идёт с ранее сохранённой
моделью текущих таблиц каждого тома, а не с новым полным исполнением старого
варианта. Хост подаёт пакеты; диск, ZX0, IRQ и ULA в этот CPU-замер не входят.
Итог: **1058467984 T**, дельта **0 T** на каждом из 4221 кадров:
[`uncontended_frame_cpu.json`](uncontended_frame_cpu.json).

Десять тестов прошли: новый тест проверяет все 256 масок присутствия,
смешанные temporal/intra/fragment-кадры и AY после каждой инструкции;
также пройдены прежние тесты очереди и безопасного paging.

Отдельный [`audit_fuse_memory.py`](audit_fuse_memory.py) после настоящего
cold boot проверил сам эмулятор. Три цикла чтения A800 заняли ровно по
**310000 T**. Те же циклы с чтением 6400 заняли **312600 / 312639 / 312865 T**.
Сырые счётчики полей/тактов подтверждают поле **70908 T** и задержки банка 5.
Это устраняет предположение о незаметном переключении Fuse на другую модель,
но величину задержки произвольного проигрывателя нельзя выводить из этого
маленького цикла. [Отчёт](uncontended_frame_machine.json).

## Полное воспроизведение в Fuse

Все три прогона завершились: 4221 публикация, 25326 AY-записей в правильном
порядке, 7501 точный сектор, ни одного retry, progress=100%.
В Fuse проверяются 80 адресов каждого кадра; полные экраны проверены CPU-стендом.

| Диск | fps было → стало | Поздних кадров было → стало | AY underruns было → стало |
|---|---:|---:|---:|
| 1 | 8,0410 → 8,0642 | 990 → 989 | 354 → 325 |
| 2 | 7,5096 → 7,5393 | 1146 → 1125 | 848 → 813 |
| 3 | 7,3606 → 7,3866 | 1272 → 1273 | 1050 → 1019 |

Частота рассчитана между первым и последним реальным OUT. Всего late
**3408 → 3387**, AY underruns **2252 → 2157**. Максимальное отставание
по полям — **330 / 819 / 1024**, по фактическим OUT —
**23470545 / 58073654 / 72609796 T**. Восстановленных серий late —
**1 / 5 / 2**; последняя серия каждой дискеты осталась невосстановленной.

Не все показатели улучшились: интервалы вне окна 5..7 полей ±64 T
**381/463/509 → 403/469/510**. Фактических OUT за пределом одного поля
**990/1146/1272 → 1091/1118/1272**. Поэтому счётчик late нельзя подменять
проверкой времени настоящего вывода. Точные AY-значения также не означают
подачу без пауз: underrun остаётся нарушением звукового расписания.

Дисковые байты/сектора неизменны. Служба чтения и seek измерены отдельно
в [сводке](uncontended_frame_summary.json), но включают ROM, IRQ, ULA и
контроллер. Фазы первого IRQ и вращения диска между вариантами не выравнивались;
разницу полных прогонов нельзя объявлять чистой экономией ULA. Физический
дисковод не проверялся.

**Решение:** сохранить перенос как проверенный дополнительный вариант,
не включать по умолчанию и не выпускать новые TRD. Средняя скорость выросла
лишь примерно на 0,3–0,4%, часть показателей интервалов ухудшилась. Это не
решает основной дефицит времени; нужен больший выигрыш в реконструкции
тяжёлых кадров и/или подготовке их заранее. Корневые TRD не заменены.

## Воспроизведение измерений

Из `.worktree/uncontended-frame`, с Python/numpy и `PYTHONPATH=toolkit`:

```powershell
python toolkit/benchmark_uncontended_frame.py --directory ../volume-huffman/.tmp/probe `
  --states ../three-disk-quality/.tmp/no_credits/source/conversion.npz `
  --model toolkit/bank_local_reservoir.json --output toolkit/uncontended_frame_cpu.json

python -m unittest toolkit/test_uncontended_frame.py toolkit/test_slot_queue.py toolkit/test_irq_safe_paging.py

python toolkit/audit_fuse_memory.py --fuse 'C:/Program Files (x86)/Fuse/fuse.exe' `
  --trd ../register-fragments/.tmp/three/ZX-video-huffman-preview_part01.trd `
  --output toolkit/uncontended_frame_machine.json

python toolkit/measure_fap3_fuse.py --fuse 'C:/Program Files (x86)/Fuse/fuse.exe' `
  --trd ../register-fragments/.tmp/three/ZX-video-huffman-preview_part01.trd `
  --metadata ../register-fragments/.tmp/three/ZX-video-huffman-preview_part01.json `
  --raw ../volume-huffman/.tmp/probe/volume-1.raw `
  --states ../three-disk-quality/.tmp/no_credits/source/conversion.npz `
  --output .tmp/fuse/part01.json --timeout 300 --slot-queue --uncontended-frame `
  --fixture-zx0 ../audio-fidelity/.tmp/bin/zx0.exe
```

Для второго и третьего прогонов заменить согласованно part01/volume-1 на
part02/volume-2 и part03/volume-3. Запускать по одному Fuse.

```powershell
python toolkit/summarize_uncontended_frame.py --fuse .tmp/fuse `
  --cpu toolkit/uncontended_frame_cpu.json --machine toolkit/uncontended_frame_machine.json `
  --evidence toolkit/uncontended_frame_evidence --output toolkit/uncontended_frame_summary.json
python toolkit/verify_uncontended_evidence.py
```

Первый запуск Fuse остановлен **до эмуляции** проверкой длины командной
строки Windows. Короткие имена команд/переменной и удаление умножения на 1
в выражениях сектора устранили превышение без сокращения покрытия.
Официальное [описание команд Fuse](https://fuse-emulator.sourceforge.net/man/html/fuse.html)
и установленный `fuse.html` описывают эти сокращения. Ранний CPU smoke
охватил 9 кадров и не считался полным; окончательные результаты сохранены отдельно.
