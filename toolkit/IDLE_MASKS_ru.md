# Пропуск масок неизменных полос: отклонённый эксперимент

25 сентября 2026, база `8c6c9f6`. Полный Fuse-прогон всех трёх дискет
оказался хуже базы со скомпилированными масками. **Вариант не включён по
умолчанию, выпуск и TRD не заменены.** Сохраняется как воспроизводимый опыт.

## Изменение

После распаковки верхнего уровня масок проверяются 12 полос по 16 плиток.
Если все 32 маски и все 16 векторов полосы нулевые, декодер оставляет её
маски в RAM нетронутыми. Флаг FFh позволяет реконструктору сразу перейти
к следующей полосе. Для активной полосы записывается флаг 0 и выполняется
прежняя распаковка четырёх групп. Все атрибутные маски раскрываются обычно.
Поток FAP3, ZX0, пиксели и AY-пакеты не меняются.

В bank 7 добавляется **133 байта** `E200..E284`; fixed bank 2 использует
**12 байтов** `BFF1..BFFC`. В работающем плеере берётся существующий
`vector_pointer` обвязки кадра; `BFFE..BFFF` — только указатель CPU-стенда.
Словари, четыре слота очереди, экраны, TR-DOS и стек не сокращаются.
Генератор скомпилированных групп и его **201509 T** до старта не изменены.

## Такты из таблицы инструкций

[`idle_masks_z80.py`](idle_masks_z80.py) сохраняет цену каждой инструкции
и независимую формулу. Верхние 8 групп и последние 12 групп атрибутов
исполняются прежним декодером. Общая обвязка: **158 → 202 T, +44 T/кадр**.

| Четыре группы одной bitmap-полосы | Было | Стало | Разница |
|---|---:|---:|---:|
| Все маски и векторы нулевые | 644 | 406, либо 405 при переносе адреса масок | −238 / −239 |
| Есть ненулевая группа масок | Сумма четырёх прежних групп | Та же сумма +169, либо +168 при переносе указателя векторов | +169 / +168 |
| Маски нулевые, есть движение/готовый фрагмент | 644 | 1004 | +360 |

Стоимость проверки на активных полосах объясняет проигрыш. В CPU-прогоне
векторы находятся с A400; реальный zero-copy пакет может начинаться иначе.
Формула учитывает переносы адреса, отдельные тесты проверяют невыравненный
вход. Поэтому конкретные такие переносы в Fuse могут отличаться от стенда.

Изменение реконструктора, от входа полосы до `regular_stripe` для активной
и до `stripe_done` для пустой; общие последующие инструкции исключены:

| Полоса | Было, T | Стало, T | Разница, T |
|---|---:|---:|---:|
| Активная внутренняя | 44 | 48 | +4 |
| Активная первая / последняя | 67 / 81 | 48 / 48 | −19 / −33 |
| Пустая внутренняя | 1460 | 204 | −1256 |
| Пустая первая / последняя | 207 / 221 | 204 / 204 | −3 / −17 |

Цена старой внутренней пустой полосы: 44 T dispatch + 20 T setup +
1396 T обход 16 пустых плиток (`scanner_tstates(16, 'end', True)`).
Новый dispatch использует `AND (HL)` с флагом FFh: 48 T; переход по
указателям без проверки первого вектора — 156 T.

## Охват CPU и прекращённые варианты

Первый вариант хранил флаг 1 и использовал `LD A,(HL); OR A`.
Его dispatch занимал 13 байтов / 52 T. На сохранённых **1001 кадре первого
диска**: **241081990 → 241541239 T, +459249**. Прогон остановлен для
замены dispatch; [его частичный отчёт](idle_masks_v1_partial.json) сохранён.
Сдвиг последующего кода на байт требовал 3692 изменённых байтов и превысил
лимит таблицы отладочного установщика. Fuse для этого варианта не запускался.

Окончательный флаг FFh позволяет использовать `AND (HL)`: **12 байтов /
48 T**, −4 T/полоса и всего 32 изменённых fixed-байта установщика.
Проверено **1825 кадров**: весь первый диск и первые 201 кадр второго.
На каждом сравнивались все 3840 compact-байтов и оба экрана по 6912 байт.
Пропущенные маски отравлены A5h; запрещены и чтение, и запись таких масок.

| CPU-охват | База, T | Опыт, T | Разница, T |
|---|---:|---:|---:|
| Диск 1, все 1624 кадра | 394673177 | 395568454 | +895277 |
| Диск 2, первые 201 | 52392634 | 52526769 | +134135 |
| Всего проверено | **447065811** | **448095223** | **+1029412** |

Из них 456 кадров быстрее, 1369 медленнее; крайние изменения −15394 и
+2424 T/кадр. Маски отдельно: 28233397 → 30245649 T, **+2012252**.
Найдено 4459 пустых полос, но лишь 809 внутренних: края уже пропускались
прежним реконструктором. Базовые суммы взяты из сохранённой полной CPU-модели
с поправкой скомпилированных масок; первые 8 кадров каждого посещённого
диска также исполнены обоими вариантами (16 пар).

После получения полных отрицательных результатов Fuse дальнейший CPU-прогон
**намеренно прекращён**, без перезапуска. Это не полная побайтовая проверка
фильма и не измерение IRQ/ULA/ROM/диска. Отчёт:
[`idle_masks_cpu_partial.json`](idle_masks_cpu_partial.json).

Прошли 4 новых opcode-теста, включая все 256 групповых масок, каждую из
192 позиций движения и 384 масок, смешанные полосы и настоящий AY IRQ
после каждой инструкции выбранных путей. Дополнительно прошли 25 прежних
тестов metadata, вывода, полос, no-op, кэша и очереди.

## Полный Fuse: три независимые загрузки до EOF

Проверены **4221 публикация, 25326 AY-записей, 7501 сектор**, все совпадают
с исходными потоками, ошибок сравнения/повторных чтений нет. На каждом кадре
сравниваются 80 контрольных адресов (служебная зона progress исключается);
это не полная попиксельная проверка в Fuse. Все диски дошли до 100% progress.

| Диск | fps было → стало | Поздних кадров | AY underruns |
|---|---|---|---|
| 1 | 8,063394 → 8,057790 | 989 → 990 | 326 → 334 |
| 2 | 7,548928 → 7,537513 | 1142 → 1147 | 803 → 816 |
| 3 | 7,393284 → 7,390760 | 1272 → 1272 | 1011 → 1014 |
| Всего | — | **3403 → 3409** | **2140 → 2164** |

Максимальное отставание: **338 / 821 / 1019 полей**; фактическое отклонение
OUT: **23966908 / 58215470 / 72255254 T**. Интервалов за пределами допуска
5..7 полей: **401 / 471 / 507**. Восстановлены 0 из 1 / 0 из 1 / 2 из 3
серий опозданий; последняя серия каждого диска не восстановлена.
Ни номинальные сроки, ни резервный допуск не выполнены.

Сумма интервалов между первой и последней публикацией трёх дисков:
**1945219164 → 1946850048 T, +1630884**. Обслуживание чтения:
235659555 → 235742262 T; seek: 5186440 → 5188288 T. Это реальные расходы
Fuse/TR-DOS, отдельно от CPU-таблицы. Начальные фазы IRQ и вращения диска
не уравнивались, поэтому разница полного времени не равна цене инструкций.

Дважды исправлялось ограничение Windows на командную строку отладчика.
Сохранены все события, AY и секторы. На дисках 2/3 выгружаются сразу те же
80 адресов целевого экрана вместо выгрузки обоих экранов с последующим
отбрасыванием нецелевых 80 значений. Диск 1 измерен прежним полным форматом
выгрузки. Смена синтаксиса отладчика не меняет инструкции плеера.

**Решение:** общий поиск пустых полос этим способом отклонён. Внедрение
невозможно обосновать выигрышем первых спокойных кадров. Потребуются выбор
операций по суммарной цене и методы, окупающиеся на активных сценах.
Новые загрузчик/ёмкость выпуска и физический дисковод не проверялись.

## Воспроизведение

Исходные три TRD/JSON: `.worktree/register-fragments/.tmp/three`, потоки:
`.worktree/volume-huffman/.tmp/probe`, состояния:
`.worktree/three-disk-quality/.tmp/no_credits/source/conversion.npz`.
Хеши входов и каждого доказательства входят в отчёты.

```text
python -m unittest test_idle_masks_z80.IdleMaskTests -v
python toolkit/benchmark_idle_masks.py --directory RAW_DIRECTORY --states STATES_NPZ --model toolkit/uncontended_frame_cpu.json --metadata-model toolkit/compiled_masks_cpu.json --output CPU_REPORT --max-frames 1825
python toolkit/measure_fap3_fuse.py --fuse FUSE_EXE --trd PART_TRD --metadata PART_JSON --raw VOLUME_RAW --states STATES_NPZ --output FUSE_REPORT --slot-queue --compiled-masks --idle-masks --fixture-zx0 ZX0_EXE --timeout 600
python toolkit/summarize_idle_masks.py
```

Для полного CPU-повтора убрать `--max-frames`. Fuse повторить отдельно для
трёх частей; корневые TRD не перезаписывать. Свежие результаты архивируются
`summarize_idle_masks.py --fuse REPORT_DIRECTORY`.

Итог и контроль хешей: [idle_masks_summary.json](idle_masks_summary.json),
[архив полных трасс](idle_masks_evidence).
